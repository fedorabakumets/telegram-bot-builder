# `db_userbot_sign_in`

## Назначение

Шаг 2: подтверждает вход Telethon кодом после `db_userbot_send_code`. При `needs_2fa: true` передаёт управление на `db_userbot_sign_in_2fa`.

## Когда использовать

Вызывай только после отправки кода для того же проекта, токена и телефона. Успешный вход сохраняет серверную сессию; бот сам не перезапускается.

## Параметры

- `project_id` — number; обязательный.
- `token_id` — number; обязательный.
- `phone` — непустая string; обязательный телефон из предыдущего шага.
- `code` — непустая string; обязательный код Telegram.

Точные типы и обязательность берутся из схемы MCP-регистрации. Перед вызовом проверь описание инструмента в MCP-клиенте; не придумывай отсутствующие поля.

## Пример вызова

```json
{
  "tool": "db_userbot_sign_in",
  "arguments": { "project_id": 42, "token_id": 7, "phone": "+79991234567", "code": "12345" }
}
```

## Пример успешного ответа

При 2FA ответ сообщает `needs_2fa`; тогда не повторяй код, а вызови `db_userbot_sign_in_2fa`. При успехе сессия сохранена.

## Типичные ошибки

- Переданы неизвестные или пропущенные обязательные параметры.
- Код просрочен или введён неверно.
- Телефон не совпадает с незавершённой авторизацией.
- Требуется пароль 2FA.

## Ограничения и безопасность

Тул может изменять live-БД, проект или состояние бота. Выполняй его только в рамках явной просьбы пользователя и проверь результат после операции.
- Не перезапускай бота автоматически; перезапуск допустим только по явной просьбе пользователя.
- После операции перечитай состояние и вызови подходящую проверку или логи.
- Если тул требует `confirm`, передавай его только после подтверждения пользователя.
