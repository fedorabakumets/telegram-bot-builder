# `db_apply_ops`

## Назначение

Применяет пакет операций к live-проекту одной транзакцией: один актуальный GET, цепочка изменений в памяти и одна запись/версия. При ошибке ни одна операция не сохраняется.

## Когда использовать

Используй для нескольких связанных изменений нод, переходов или листов. Только по явной просьбе изменить live-проект; перед этим перечитай актуальное состояние и проверь план.

## Параметры

- `project_id` — number; обязательный параметр.
- `ops` — непустой array объектов; обязательный. Поддерживаемые `op`: `add_node`, `update_node`, `remove_node`, `connect_nodes`, `disconnect_nodes`, `move_node`, `duplicate_node`, `add_sheet`, `rename_sheet`, `remove_sheet`, `duplicate_sheet`, `set_active_sheet`.
- `commit_message` — string; необязательный параметр.
- `skip_validation` — boolean; необязательный параметр.

Точные типы и обязательность берутся из схемы MCP-регистрации. Перед вызовом проверь описание инструмента в MCP-клиенте; не придумывай отсутствующие поля.

## Пример вызова

```json
{
  "tool": "db_apply_ops",
  "arguments": {
    "project_id": 42,
    "ops": [
      { "op": "add_node", "node": { "id": "hello", "type": "message", "position": { "x": 0, "y": 0 }, "data": { "messageText": "Привет", "buttons": [], "keyboardType": "none" } } },
      { "op": "connect_nodes", "from_id": "start", "to_id": "hello" }
    ],
    "commit_message": "Добавлен приветственный сценарий"
  }
}
```

## Пример успешного ответа

Успешный ответ содержит применённый проект и результат валидации. Ошибка содержит индекс неудачной операции; запись при этом не выполняется.

## Типичные ошибки

- `ops` пустой или содержит неизвестный `op`.
- Целевая нода/лист отсутствует, ID ноды дублируется.
- `connect_nodes` использует неправильную ветку или порт.
- Проект не проходит валидацию; `skip_validation` не следует использовать для нового сценария.

## Ограничения и безопасность

Тул может изменять live-БД, проект или состояние бота. Выполняй его только в рамках явной просьбы пользователя и проверь результат после операции.
- Не перезапускай бота автоматически; перезапуск допустим только по явной просьбе пользователя.
- После операции перечитай состояние и вызови подходящую проверку или логи.
- Если тул требует `confirm`, передавай его только после подтверждения пользователя.

## Связанные инструменты

- `get_tool_docs` — получить карточку этого и связанных тулов.
- `search_tool_docs` — найти подходящие инструменты.
- `get_workflow_docs` — получить рекомендуемую последовательность действий.

## Рекомендуемый следующий шаг

После успеха перечитай проект, проверь `validate_bot_project` и только затем выполняй отдельную live-операцию запуска.
