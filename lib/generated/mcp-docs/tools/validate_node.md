# `validate_node`

## Назначение

Проверяет одну ноду по схеме конструктора и, если передан `type`, сверяет фактический тип с ожидаемым. Read-only: проект не изменяет.

## Когда использовать

Вызывай сразу после `create_node` или перед добавлением вручную собранной ноды в `project.json`. Это локальная проверка полей ноды, а не проверка связей между нодами.

## Параметры

- `node` — record; обязательный параметр.
- `type` — string; необязательный параметр.

Точные типы и обязательность берутся из схемы MCP-регистрации. Перед вызовом проверь описание инструмента в MCP-клиенте; не придумывай отсутствующие поля.

## Пример вызова

```json
{
  "tool": "validate_node",
  "arguments": {
    "type": "input",
    "node": {
      "id": "input-email",
      "type": "input",
      "position": { "x": 420, "y": 180 },
      "data": { "inputVariable": "email", "inputType": "text", "validationType": "email" }
    }
  }
}
```

## Пример успешного ответа

Успешный ответ содержит результат проверки. При ошибке исправь указанное поле и повтори проверку; одного успешного транспорта недостаточно.

## Типичные ошибки

- Переданы неизвестные или пропущенные обязательные параметры.
- Передан не полный объект `{id, type, position, data}`.
- `type` не совпадает с `node.type`.
- В `data` использовано поле или enum-значение не из схемы.

## Ограничения и безопасность

Тул только читает данные или выполняет проверку; он не должен изменять проект, БД или состояние бота.
- Не трактуй отсутствие ошибки транспорта как подтверждение бизнес-корректности результата.
- Для дальнейшего изменения используй отдельный mutating-тул после проверки данных.

## Связанные инструменты

- `get_tool_docs` — получить карточку этого и связанных тулов.

## Рекомендуемый следующий шаг

После успешной проверки добавь ноду в проект, подключи переходы и вызови `validate_bot_project`.
