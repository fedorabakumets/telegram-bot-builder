# `db_bot_logs`

## Назначение

Возвращает последние live-логи бота (`stdout`, `stderr`, `status`) для быстрой отладки. Секрет токена не возвращается.

## Когда использовать

Вызывай после `db_start_bot`/`db_restart_bot`, если статус не стал `running`, или после проверки сценария в Telegram. `token_id` бери из `db_list_bot_tokens`.

## Параметры

- `project_id` — number; обязательный параметр.
- `token_id` — number; обязательный параметр.
- `limit` — number; необязательный параметр.

Точные типы и обязательность берутся из схемы MCP-регистрации. Перед вызовом проверь описание инструмента в MCP-клиенте; не придумывай отсутствующие поля.

## Пример вызова

```json
{
  "tool": "db_bot_logs",
  "arguments": { "project_id": 42, "token_id": 7, "limit": 100 }
}
```

## Пример успешного ответа

Ответ содержит записи stdout/stderr/status. Используй `stderr` для причины сбоя, `status` — для событий запуска.

## Типичные ошибки

- Переданы неизвестные или пропущенные обязательные параметры.
- `project_id` и `token_id` не соответствуют друг другу.
- Логи ещё не появились: запуск асинхронный, проверь позже.
- Агент ищет ошибку только в stdout, игнорируя stderr.

## Ограничения и безопасность

Тул может изменять live-БД, проект или состояние бота. Выполняй его только в рамках явной просьбы пользователя и проверь результат после операции.
- Не перезапускай бота автоматически; перезапуск допустим только по явной просьбе пользователя.
- После операции перечитай состояние и вызови подходящую проверку или логи.
- Если тул требует `confirm`, передавай его только после подтверждения пользователя.

## Связанные инструменты

## Рекомендуемый следующий шаг

Сопоставь ошибку с последним изменением ноды, исправь проект и снова проверь `validate_bot_project`; не перезапускай бесконечно без новой причины.
