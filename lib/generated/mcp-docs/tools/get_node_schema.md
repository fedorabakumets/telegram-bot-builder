# `get_node_schema`

## Назначение

Возвращает фактическую схему `data`, допустимые значения enum и правила конкретного типа ноды. Это главный read-only тул перед созданием или изменением ноды.

## Когда использовать

Вызывай его, если тип ноды незнаком, нужно добавить поле, настроить режим или исправить ошибку валидации. Не подменяй его документацией Telegram.

## Параметры

- `type` — string; обязательный параметр.

Точные типы и обязательность берутся из схемы MCP-регистрации. Перед вызовом проверь описание инструмента в MCP-клиенте; не придумывай отсутствующие поля.

## Пример вызова

```json
{
  "tool": "get_node_schema",
  "arguments": { "type": "set_variable" }
}
```

## Пример успешного ответа

Ответ содержит тип ноды, описание полей `data`, обязательность, значения по умолчанию и допустимые enum. Для `condition` отдельно используй `list_operators`, а для рабочего JSON — `get_node_example`.

## Типичные ошибки

- Переданы неизвестные или пропущенные обязательные параметры.
- `type` не входит в доступные типы MCP: сначала вызови `list_node_types`.
- Запрошен запрещённый legacy-тип.
- Агент взял поле из старой документации и не сверил актуальную схему.

## Ограничения и безопасность

Тул только читает данные или выполняет проверку; он не должен изменять проект, БД или состояние бота.
- Не трактуй отсутствие ошибки транспорта как подтверждение бизнес-корректности результата.
- Для дальнейшего изменения используй отдельный mutating-тул после проверки данных.

## Связанные инструменты

- `get_tool_docs` — получить карточку этого и связанных тулов.
- `search_tool_docs` — найти подходящие инструменты.
- `get_workflow_docs` — получить рекомендуемую последовательность действий.

## Рекомендуемый следующий шаг

Скопируй допустимую форму `data`, вызови `get_node_example`, затем создай ноду через `create_node` и проверь её через `validate_node`.
