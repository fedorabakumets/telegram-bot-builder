# `list_operators`

## Назначение

Возвращает белый список операторов `condition`-ноды и ограничения совместимости с валидатором.

## Когда использовать

Вызывай перед созданием или исправлением ветвления. Не придумывай `is_empty`/`not_empty`: используй только значения из ответа этого тула и схемы ноды.

## Параметры

- Инструмент не объявляет именованных параметров.

Точные типы и обязательность берутся из схемы MCP-регистрации. Перед вызовом проверь описание инструмента в MCP-клиенте; не придумывай отсутствующие поля.

## Пример вызова

```json
{
  "tool": "list_operators",
  "arguments": {}
}
```

## Пример успешного ответа

Ответ содержит списки допустимых и запрещённых операторов. Для каждой ветки всё равно укажи `operator`, `value` и `target` в формате `condition`-ноды.

## Типичные ошибки

- Использован оператор, которого нет в белом списке.
- Перепутан оператор с именем поля (`conditions`, `defaultTarget`).
- Ветка `else` создана не последней или указывает на отсутствующую ноду.

## Ограничения и безопасность

Тул только читает данные или выполняет проверку; он не должен изменять проект, БД или состояние бота.
- Не трактуй отсутствие ошибки транспорта как подтверждение бизнес-корректности результата.
- Для дальнейшего изменения используй отдельный mutating-тул после проверки данных.

## Связанные инструменты

- `get_tool_docs` — получить карточку этого и связанных тулов.
- `search_tool_docs` — найти подходящие инструменты.
- `get_workflow_docs` — получить рекомендуемую последовательность действий.
