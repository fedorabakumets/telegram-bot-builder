# `scaffold_minimal_project`

## Назначение

Создаёт локальный минимальный `project.json` v2 со стартовой парой `/start → message` или с переданным массивом нод. Live-проект не изменяет.

## Когда использовать

Используй как безопасную основу нового сценария, когда нет готового проекта. В команде используй только латиницу; затем расширяй JSON и проверяй его валидатором.

## Параметры

- `sheet_name` — string; необязательное имя листа.
- `nodes` — array<object>; необязательный массив готовых нод, заменяющий дефолтный набор.

Точные типы и обязательность берутся из схемы MCP-регистрации. Перед вызовом проверь описание инструмента в MCP-клиенте; не придумывай отсутствующие поля.

## Пример вызова

```json
{
  "tool": "scaffold_minimal_project",
  "arguments": { "sheet_name": "Калькулятор" }
}
```

## Пример успешного ответа

Ответ содержит готовый JSON проекта. Проверь его через `validate_bot_project`, затем добавляй ноды/связи или сохраняй проект отдельным инструментом.

## Типичные ошибки

- `nodes` содержит ноду с неверным форматом или дублирующимся ID.
- Передан кириллический `command_trigger` вместо латинской команды.
- Агент считает локальный результат уже сохранённым в БД.

## Ограничения и безопасность

Тул только читает данные или выполняет проверку; он не должен изменять проект, БД или состояние бота.
- Не трактуй отсутствие ошибки транспорта как подтверждение бизнес-корректности результата.
- Для дальнейшего изменения используй отдельный mutating-тул после проверки данных.

## Связанные инструменты

- `get_tool_docs` — получить карточку этого и связанных тулов.
- `search_tool_docs` — найти подходящие инструменты.
- `get_workflow_docs` — получить рекомендуемую последовательность действий.

## Рекомендуемый следующий шаг

Проверь JSON, добавь сценарий через `add_node`/`connect_nodes`, затем сохрани его только после успешной валидации.
