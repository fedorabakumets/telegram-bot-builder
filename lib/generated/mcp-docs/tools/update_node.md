# `update_node`

## Назначение

Обновляет одну ноду в переданном `project.json` по ID. Без `sheet_id` ищет по всем листам; если нода не найдена, возвращает ошибку.

## Когда использовать

Используй для локальной правки `data`, `position` или допустимого `type`. Сначала прочитай текущую ноду, не заменяй `data` догадками. Для live-проекта используй `db_update_node`.

## Параметры

- `project_json` — union; обязательный параметр.
- `node_id` — string; обязательный параметр.
- `patch` — record; обязательный параметр.
- `sheet_id` — string; необязательный параметр.

Точные типы и обязательность берутся из схемы MCP-регистрации. Перед вызовом проверь описание инструмента в MCP-клиенте; не придумывай отсутствующие поля.

## Пример вызова

```json
{
  "tool": "update_node",
  "arguments": {
    "project_json": { "version": 2, "nodes": [ { "id": "hello", "type": "message", "position": { "x": 0, "y": 0 }, "data": { "messageText": "Привет", "buttons": [], "keyboardType": "none" } } ], "edges": [] },
    "node_id": "hello",
    "patch": { "data": { "messageText": "Здравствуйте" } }
  }
}
```

## Пример успешного ответа

Ответ содержит обновлённый `project_json`. После патча проверь ноду и весь проект; переходы и кнопки автоматически не исправляются.

## Типичные ошибки

- Переданы неизвестные или пропущенные обязательные параметры.
- `node_id` отсутствует или найден на другом листе.
- `patch` заменил обязательные поля `data` неполным объектом.
- Новый тип не соответствует схеме.

## Ограничения и безопасность

Тул может изменять live-БД, проект или состояние бота. Выполняй его только в рамках явной просьбы пользователя и проверь результат после операции.
- Не перезапускай бота автоматически; перезапуск допустим только по явной просьбе пользователя.
- После операции перечитай состояние и вызови подходящую проверку или логи.
- Если тул требует `confirm`, передавай его только после подтверждения пользователя.
