# `db_bot_status`

## Назначение

Read-only статус бота по `token_id`: `running/stopped`, имя, username, uptime и статистика пользователей. Секрет `token` не возвращается.

## Когда использовать

Вызывай после `db_start_bot`, `db_restart_bot`, изменения токена или при диагностике. `token_id` сначала получи через `db_list_bot_tokens`.

## Параметры

- `token_id` — number; обязательный параметр.

Точные типы и обязательность берутся из схемы MCP-регистрации. Перед вызовом проверь описание инструмента в MCP-клиенте; не придумывай отсутствующие поля.

## Пример вызова

```json
{
  "tool": "db_bot_status",
  "arguments": { "token_id": 7 }
}
```

## Пример успешного ответа

Считай бот запущенным только при фактическом статусе `running`. `starting`, отсутствие процесса или старый uptime требуют проверки логов.

## Типичные ошибки

- Переданы неизвестные или пропущенные обязательные параметры.
- `token_id` не существует или недоступен.
- Агент перепутал статус постановки задачи со статусом процесса.
- При `stopped` не проверены `db_bot_logs` и история запусков.

## Ограничения и безопасность

Тул только читает данные или выполняет проверку; он не должен изменять проект, БД или состояние бота.
- Не трактуй отсутствие ошибки транспорта как подтверждение бизнес-корректности результата.
- Для дальнейшего изменения используй отдельный mutating-тул после проверки данных.

## Связанные инструменты

- `get_tool_docs` — получить карточку этого и связанных тулов.
- `search_tool_docs` — найти подходящие инструменты.
- `get_workflow_docs` — получить рекомендуемую последовательность действий.

## Рекомендуемый следующий шаг

При `running` можно сообщить об успехе; при ошибке вызови `db_bot_logs` и `db_bot_launch_history`, не запускай restart автоматически.
