# `db_import_table_file`

## Назначение

Импортирует CSV или JSON-файл в пользовательскую таблицу. Разрешены только локальный рабочий каталог и временная папка; URL и чужие пути запрещены.

## Когда использовать

Сначала проверь таблицу и формат файла. `append` добавляет строки, `replace` заменяет содержимое и требует `confirm: true`, который можно передать только после явного подтверждения пользователя.

## Параметры

- `project_id` — number; обязательный параметр.
- `table_id` — number; обязательный параметр.
- `path` — string; обязательный параметр.
- `mode` — `append | replace`; обязательный режим.
- `confirm` — boolean; необязательный параметр.

Точные типы и обязательность берутся из схемы MCP-регистрации. Перед вызовом проверь описание инструмента в MCP-клиенте; не придумывай отсутствующие поля.

## Пример вызова

```json
{
  "tool": "db_import_table_file",
  "arguments": { "project_id": 42, "table_id": 12, "path": "C:\\temp\\orders.csv", "mode": "append" }
}
```

## Пример успешного ответа

Ответ содержит результат импорта и число обработанных строк. После записи проверь строки через `db_list_table_rows`.

## Типичные ошибки

- Файл отсутствует, недоступен или находится вне разрешённого каталога.
- Формат не CSV/JSON или строки не соответствуют столбцам таблицы.
- Для `replace` отсутствует `confirm: true`.

## Ограничения и безопасность

Тул изменяет строки таблицы. Он не принимает URL и не раскрывает произвольные файлы сервера.
- Не трактуй отсутствие ошибки транспорта как подтверждение бизнес-корректности результата.
- Для дальнейшего изменения используй отдельный mutating-тул после проверки данных.

## Связанные инструменты

- `get_tool_docs` — получить карточку этого и связанных тулов.
- `search_tool_docs` — найти подходящие инструменты.
- `get_workflow_docs` — получить рекомендуемую последовательность действий.

## Рекомендуемый следующий шаг

После успешного импорта перечитай таблицу, затем проверь сценарий `bot_table`, который использует эти данные.
