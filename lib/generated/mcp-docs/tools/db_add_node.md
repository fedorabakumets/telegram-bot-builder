# `db_add_node`

## Назначение

Добавляет ноду непосредственно в live-проект по числовому `project_id` и обновляет холст через API. Операция изменяет БД и создаёт версию проекта.

## Когда использовать

Используй только после явной просьбы изменить live-проект. Перед вызовом получи схему/пример ноды, проверь её и убедись, что ID уникален. Для локального JSON используй `add_node`.

## Параметры

- `project_id` — number; обязательный параметр.
- `node` — record; обязательный параметр.
- `sheet_id` — string; необязательный параметр.
- `commit_message` — string; необязательный параметр.

Точные типы и обязательность берутся из схемы MCP-регистрации. Перед вызовом проверь описание инструмента в MCP-клиенте; не придумывай отсутствующие поля.

## Пример вызова

```json
{
  "tool": "db_add_node",
  "arguments": {
    "project_id": 42,
    "node": { "id": "hello", "type": "message", "position": { "x": 0, "y": 0 }, "data": { "messageText": "Привет", "buttons": [], "keyboardType": "none" } },
    "commit_message": "Добавлено приветственное сообщение"
  }
}
```

## Пример успешного ответа

Успешный ответ подтверждает запись ноды и содержит актуальное состояние/версию. После записи перечитай проект и проверь связи.

## Типичные ошибки

- Переданы неизвестные или пропущенные обязательные параметры.
- Нода не прошла схему или её ID уже существует.
- `project_id` неверен или доступ запрещён.
- Нода добавлена без входящего/исходящего перехода.

## Ограничения и безопасность

Тул может изменять live-БД, проект или состояние бота. Выполняй его только в рамках явной просьбы пользователя и проверь результат после операции.
- Не перезапускай бота автоматически; перезапуск допустим только по явной просьбе пользователя.
- После операции перечитай состояние и вызови подходящую проверку или логи.
- Если тул требует `confirm`, передавай его только после подтверждения пользователя.

## Связанные инструменты
