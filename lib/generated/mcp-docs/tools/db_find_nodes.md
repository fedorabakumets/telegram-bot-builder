# `db_find_nodes`

## Назначение

Ищет ноды по регистронезависимой подстроке в тексте, команде, ID и полях кнопок `url`, `copyText`, `text`. Read-only.

## Когда использовать

Используй для поиска интеграционной ноды по тексту сообщения, URL внешнего API или имени ID. Это не поиск по произвольному Python-коду и не SQL.

## Параметры

- `project_id` — number; обязательный параметр.
- `query` — string; обязательный параметр.
- `type` — string; необязательный параметр.
- `sheet_id` — string; необязательный параметр.

Точные типы и обязательность берутся из схемы MCP-регистрации. Перед вызовом проверь описание инструмента в MCP-клиенте; не придумывай отсутствующие поля.

## Пример вызова

```json
{
  "tool": "db_find_nodes",
  "arguments": { "project_id": 42, "query": "api.example.com", "type": "http_request" }
}
```

## Пример успешного ответа

Ответ содержит совпадения с ID и листом. Получи нужную ноду через `db_get_node`, прежде чем менять её.

## Типичные ошибки

- Переданы неизвестные или пропущенные обязательные параметры.
- `query` пустой или `type` не совпадает с фактическим типом.
- Поиск не находит значения внутри произвольного `code`-текста.
- Найденная нода относится к другому листу, но `sheet_id` проигнорирован.

## Ограничения и безопасность

Тул только читает данные или выполняет проверку; он не должен изменять проект, БД или состояние бота.
- Не трактуй отсутствие ошибки транспорта как подтверждение бизнес-корректности результата.
- Для дальнейшего изменения используй отдельный mutating-тул после проверки данных.

## Связанные инструменты

- `search_tool_docs` — найти подходящие инструменты.
