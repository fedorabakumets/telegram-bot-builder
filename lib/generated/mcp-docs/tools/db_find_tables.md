# `db_find_tables`

## Назначение

Ищет пользовательские таблицы проекта по части имени и возвращает их ID. Read-only; системные таблицы не возвращаются.

## Когда использовать

Используй, когда имя таблицы известно неточно или проект содержит несколько таблиц. Если нужно перечислить все таблицы, используй `db_list_tables`.

## Параметры

- `project_id` — number; обязательный.
- `query` — string; обязательная часть имени.
- `limit` — integer; необязательный диапазон 1–100.

Точные типы и обязательность берутся из схемы MCP-регистрации. Перед вызовом проверь описание инструмента в MCP-клиенте; не придумывай отсутствующие поля.

## Пример вызова

```json
{
  "tool": "db_find_tables",
  "arguments": { "project_id": 42, "query": "заказ", "limit": 20 }
}
```

## Пример успешного ответа

Ответ содержит совпавшие таблицы и их `table_id`. Перед чтением столбцов передай выбранный ID в `db_get_table`.

## Типичные ошибки

- `query` пустой или `limit` вне диапазона 1–100.
- Совпадений нет — это не ошибка; уточни запрос или используй список.
- Таблица принадлежит другому проекту.

## Ограничения и безопасность

Тул только читает данные или выполняет проверку; он не должен изменять проект, БД или состояние бота.
- Не трактуй отсутствие ошибки транспорта как подтверждение бизнес-корректности результата.
- Для дальнейшего изменения используй отдельный mutating-тул после проверки данных.

## Связанные инструменты

- `search_tool_docs` — найти подходящие инструменты.

## Рекомендуемый следующий шаг

Выбери нужный `table_id`, получи столбцы и только потом выполняй операции строк.
