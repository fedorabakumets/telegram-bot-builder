# command_trigger-нода

## Назначение

Нода типа command_trigger выполняет специализированное действие конструктора.

## Формат и поведение

Канонические поля, обязательность, значения по умолчанию и допустимые значения определяются фактической схемой ноды и рабочим примером. Перед созданием или изменением вызови get_node_schema(command_trigger) и get_node_example(command_trigger); не добавляй поля по аналогии с Telegram API. Цели переходов должны ссылаться на существующие ID нод.

Сохраняй переменные без фигурных скобок в полях-источниках, а подстановку в текстах записывай как {name}. Если функция не реализована конкретной схемой или runtime, указывай «не поддерживается».

## Минимальный рабочий шаблон

```json
{"id":"command_trigger-1","type":"command_trigger","position":{"x":0,"y":0},"data":{}}
```

Перед сохранением замени data на форму, возвращённую get_node_example; пустой шаблон сам по себе не гарантирует валидность.

## Частые ошибки

- поле взято из другого типа ноды;
- цель перехода отсутствует;
- переменная указана со скобками там, где ожидается её имя;
- не проверены права Telegram, таймауты и ответ runtime;
- не просмотрены логи при ошибке.

## Связанные ноды

message, condition, input, code, set_variable и ноды, указанные в поле перехода конкретной схемы.

## Как проверить результат

Вызови get_node_schema(command_trigger), get_node_example(command_trigger), затем validate_node и validate_bot_project. Для live-поведения проверь логи бота и фактический ответ Telegram/API. Просмотр runtime-контекста пользователя через MCP не реализован.

## Следующий шаг

После проверки соедини ноду с целевой нодой и воспроизведи сценарий на тестовом пользователе.
