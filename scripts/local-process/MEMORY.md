Локальное измерение 11 ноября 2026 года: Windows, Python 3.14 из `.venv`, настоящий
`server/python/worker.py`, локальный Redis, синтетический Telegram HTTP. Бот-фикистура
создаёт и трогает 64 МиБ страниц памяти; настоящие боты, токены и S3 не используются.

Запуск: `.venv/Scripts/python.exe scripts/local-process/memory-probe.py`.
Измерение импортов отдельно: та же команда с `--baseline`.

| Состояние | Родитель RSS, МиБ | Обработчик RSS, МиБ | Лаунчер Windows, МиБ | Сумма RSS, МиБ |
| --- | ---: | ---: | ---: | ---: |
| Воркер готов, без ботов | 21,7 | — | — | 21,7 |
| Приёмник зарегистрирован | 47,5 | — | — | 47,5 |
| Цикл 1, обработка | 48,1 | 145,8 | 3,3 | 197,2 |
| Цикл 1, после простоя | 48,1 | процесс завершён | завершён | 48,1 |
| Цикл 2, обработка | 48,2 | 146,0 | 3,3 | 197,5 |
| Цикл 2, после простоя | 48,2 | процесс завершён | завершён | 48,2 |

Процессы обработчиков имели разные PID; проверялось исчезновение PID после каждого
простоя. Это подтверждает освобождение памяти обработчика операционной системой,
а не только удаление ссылки на модуль Python. Базовая память общего приёмника
остаётся около 48 МиБ: нулевой расход на всю систему не обещается.

Отдельный чистый процесс до изменений точки загрузки: Python 14,4 МиБ RSS,
импорт worker 23,0 МиБ, вызов `lazy_aiogram.enable()` 71,8 МиБ.
Последний вызов импортирует aiogram целиком, несмотря на название «lazy».
В процессном режиме он перенесён в обработчик, поэтому родитель его не загружает.

RSS Windows означает рабочий набор. Private bytes измеряются отдельно и не
прибавляются к RSS. Сумма RSS может дважды учитывать общие страницы нескольких
процессов; это не уникальная физическая память и не метрика Linux cgroup/Railway.
Результат синтетический, не прогноз памяти реальных сценариев или production.
