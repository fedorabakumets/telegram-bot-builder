# Runtime-контекст

Обычные пользовательские ноды выполняются в контексте текущего пользователя и его FSM. `input` ожидает один следующий ответ; параллельные конкурирующие input-ветки запрещены.

Переменные пользователя доступны следующим нодам сценария. `schedule_trigger` не имеет текущего пользователя и не должен использовать `{user_id}` без явного получателя. Для расследования используй `db_bot_status`, `db_bot_logs` и поиск логов.
