# `db_find_table_rows`

## Назначение

Ищет строки максимум по пяти условиям без произвольного SQL. Поддерживаются `equals`, `not_equals`, `contains`, `starts_with`, `ends_with`, `filled`, `empty`, `greater_than`, `less_than`.

## Когда использовать

Сначала получи ID столбцов через `db_list_table_columns`. Для одного условия всё равно передавай массив `filters`; значения сравниваются как строки по правилам API.

## Параметры

- `project_id` — number; обязательный параметр.
- `table_id` — number; обязательный параметр.
- `filters` — array; обязательный параметр.
- `limit` — number; необязательный параметр.
- `offset` — number; необязательный параметр.
- `sort` — string; необязательный параметр.
- `columns` — array; необязательный параметр.

Точные типы и обязательность берутся из схемы MCP-регистрации. Перед вызовом проверь описание инструмента в MCP-клиенте; не придумывай отсутствующие поля.

## Пример вызова

```json
{
  "tool": "db_find_table_rows",
  "arguments": { "project_id": 42, "table_id": 12, "filters": [ { "column_id": 102, "operator": "equals", "value": "Новый" } ], "limit": 100 }
}
```

## Пример успешного ответа

Ответ содержит найденные строки и параметры страницы. Для количества совпадений без строк используй `db_count_table_rows`.

## Типичные ошибки

- Передано больше пяти фильтров.
- `column_id` не существует в таблице.
- Для `filled`/`empty` передано лишнее или неподходящее значение.
- Агент попытался передать SQL вместо фильтра.

## Ограничения и безопасность

Тул только читает данные или выполняет проверку; он не должен изменять проект, БД или состояние бота.
- Не трактуй отсутствие ошибки транспорта как подтверждение бизнес-корректности результата.
- Для дальнейшего изменения используй отдельный mutating-тул после проверки данных.
