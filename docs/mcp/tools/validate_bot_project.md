# `validate_bot_project`

## Назначение

Проверяет весь `project.json`: структуру Zod, типы нод, дубли ID, цели переходов и правила `condition`/команд. Read-only.

## Когда использовать

Вызывай после каждой группы изменений и обязательно до сохранения, запуска или публикации проекта. Он проверяет связи, которые не видны в `validate_node`.

## Параметры

- `project_json` — union; обязательный параметр.

Точные типы и обязательность берутся из схемы MCP-регистрации. Перед вызовом проверь описание инструмента в MCP-клиенте; не придумывай отсутствующие поля.

## Пример вызова

```json
{
  "tool": "validate_bot_project",
  "arguments": {
    "project_json": {
      "version": 2,
      "nodes": [
        { "id": "start", "type": "command_trigger", "position": { "x": 0, "y": 0 }, "data": { "command": "/start", "autoTransitionTo": "hello" } },
        { "id": "hello", "type": "message", "position": { "x": 260, "y": 0 }, "data": { "messageText": "Привет", "buttons": [], "keyboardType": "none" } }
      ],
      "edges": []
    }
  }
}
```

## Пример успешного ответа

Успех означает, что JSON прошёл схему и доменные проверки. Ошибки содержат путь или правило; исправляй проект, а не обходи проверку через `skip_validation`.

## Типичные ошибки

- Переданы неизвестные или пропущенные обязательные параметры.
- Дублируются `nodes[].id`.
- `autoTransitionTo`, `target` или branch указывает на отсутствующий ID.
- У `condition` использован формат `conditions/defaultTarget` или запрещённый оператор.
- Команда содержит кириллицу: используй `/buy`, а не `/купить`.

## Ограничения и безопасность

Тул только читает данные или выполняет проверку; он не должен изменять проект, БД или состояние бота.
- Не трактуй отсутствие ошибки транспорта как подтверждение бизнес-корректности результата.
- Для дальнейшего изменения используй отдельный mutating-тул после проверки данных.

## Связанные инструменты

- `get_tool_docs` — получить карточку этого и связанных тулов.
- `search_tool_docs` — найти подходящие инструменты.
- `get_workflow_docs` — получить рекомендуемую последовательность действий.

## Рекомендуемый следующий шаг

После успеха можно сохранять проект или выполнять явно запрошенную live-операцию. При ошибке не запускай бота.
