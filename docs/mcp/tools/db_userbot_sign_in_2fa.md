# `db_userbot_sign_in_2fa`

## Назначение

Шаг 3 авторизации: проверяет пароль 2FA после ответа `needs_2fa: true`. Сессия сохраняется сервером, автоматического запуска нет.

## Когда использовать

Вызывай только для того же проекта и токена, где успешно прошёл `db_userbot_sign_in`. Не передавай пароль в логи или повторные сообщения.

## Параметры

- `project_id` — number; обязательный.
- `token_id` — number; обязательный.
- `password` — непустая string; обязательный пароль Telegram 2FA.

Точные типы и обязательность берутся из схемы MCP-регистрации. Перед вызовом проверь описание инструмента в MCP-клиенте; не придумывай отсутствующие поля.

## Пример вызова

```json
{
  "tool": "db_userbot_sign_in_2fa",
  "arguments": { "project_id": 42, "token_id": 7, "password": "пароль-пользователя" }
}
```

## Пример успешного ответа

Успех означает, что сессия Userbot сохранена. Пароль и session string не должны возвращаться агенту.

## Типичные ошибки

- Переданы неизвестные или пропущенные обязательные параметры.
- Вызов сделан без активного шага 2FA.
- Пароль неверен или аккаунт требует другой способ подтверждения.
- ID проекта и токена не совпадают с авторизационной сессией.

## Ограничения и безопасность

Тул может изменять live-БД, проект или состояние бота. Выполняй его только в рамках явной просьбы пользователя и проверь результат после операции.
- Не перезапускай бота автоматически; перезапуск допустим только по явной просьбе пользователя.
- После операции перечитай состояние и вызови подходящую проверку или логи.
- Если тул требует `confirm`, передавай его только после подтверждения пользователя.

## Связанные инструменты

- `get_tool_docs` — получить карточку этого и связанных тулов.
- `search_tool_docs` — найти подходящие инструменты.
- `get_workflow_docs` — получить рекомендуемую последовательность действий.

## Рекомендуемый следующий шаг

Проверь результат и только по явной просьбе пользователя вызови `db_start_bot` или `db_restart_bot`.
