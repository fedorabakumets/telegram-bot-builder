# `db_apply_table_ops`

## Назначение

Выполняет до 50 операций над таблицей одной транзакцией: столбцы, строки и переиндексация. При ошибке транзакция откатывается; ответ содержит `failed_op_index`.

## Когда использовать

Используй для атомарного набора изменений, когда важно применить все операции вместе. Перед удалением передай `confirm: true` только после явного подтверждения пользователя.

## Параметры

- `project_id` — number; обязательный параметр.
- `table_id` — number; обязательный параметр.
- `confirm` — boolean; необязательный параметр.
- `ops` — array; обязательный параметр.

Точные типы и обязательность берутся из схемы MCP-регистрации. Перед вызовом проверь описание инструмента в MCP-клиенте; не придумывай отсутствующие поля.

## Пример вызова

```json
{
  "tool": "db_apply_table_ops",
  "arguments": {
    "project_id": 42,
    "table_id": 12,
    "ops": [
      { "op": "add_column", "name": "Статус" },
      { "op": "add_rows", "rows": [ { "data": { "101": "Новый" } } ] }
    ]
  }
}
```

## Пример успешного ответа

Успех означает, что весь пакет применён. При ошибке смотри `failed_op_index`, исправь конкретную операцию и повтори пакет после проверки текущего состояния.

## Типичные ошибки

- В `ops` больше 50 операций или неизвестное имя операции.
- Операция ссылается на чужой столбец/строку.
- Есть удаление, но не передан `confirm: true`.
- Пакет построен на устаревших ID после изменения таблицы.

## Ограничения и безопасность

Тул может изменять live-БД, проект или состояние бота. Выполняй его только в рамках явной просьбы пользователя и проверь результат после операции.
- Не перезапускай бота автоматически; перезапуск допустим только по явной просьбе пользователя.
- После операции перечитай состояние и вызови подходящую проверку или логи.
- Если тул требует `confirm`, передавай его только после подтверждения пользователя.
