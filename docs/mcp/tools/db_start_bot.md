# `db_start_bot`

## Назначение

Запускает бота проекта в live-приложении. Операция асинхронная, пишет запуск в историю и обновляет UI; секрет `botToken` сервер берёт сам и не возвращает агенту.

## Когда использовать

Используй только по явной просьбе пользователя и после успешной проверки проекта. Если нужен конкретный бот из нескольких, передай его `token_id`; иначе используется дефолтный токен проекта.

## Параметры

- `project_id` — number; обязательный параметр.
- `token_id` — number; необязательный параметр.

Точные типы и обязательность берутся из схемы MCP-регистрации. Перед вызовом проверь описание инструмента в MCP-клиенте; не придумывай отсутствующие поля.

## Пример вызова

```json
{
  "tool": "db_start_bot",
  "arguments": { "project_id": 42, "token_id": 7 }
}
```

## Пример успешного ответа

Успешный ответ означает, что запуск принят, но не гарантирует `running`. Через короткий интервал проверь `db_bot_status`, при ошибке — `db_bot_logs`.

## Типичные ошибки

- Переданы неизвестные или пропущенные обязательные параметры.
- Проект не найден или токен не принадлежит проекту.
- Проект невалиден, отсутствует токен или бот уже запускается.
- Агент не дождался фактического статуса и сообщил о запуске преждевременно.

## Ограничения и безопасность

Тул может изменять live-БД, проект или состояние бота. Выполняй его только в рамках явной просьбы пользователя и проверь результат после операции.
- Не перезапускай бота автоматически; перезапуск допустим только по явной просьбе пользователя.
- После операции перечитай состояние и вызови подходящую проверку или логи.
- Если тул требует `confirm`, передавай его только после подтверждения пользователя.

## Связанные инструменты

- `get_tool_docs` — получить карточку этого и связанных тулов.
- `search_tool_docs` — найти подходящие инструменты.
- `get_workflow_docs` — получить рекомендуемую последовательность действий.

## Рекомендуемый следующий шаг

Проверь `db_bot_status`; при `stopped`/ошибке прочитай логи. Не вызывай повторный старт без анализа результата.
