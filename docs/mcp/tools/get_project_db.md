# `get_project_db`

## Назначение

Читает полный сценарий live-проекта из БД и возвращает `BotDataWithSheets`. Операция тяжёлая, но read-only; `project_id` — числовой ID из URL редактора.

## Когда использовать

Вызывай перед live-изменением нод или пакетных операций, чтобы работать с актуальной версией. Не используй для простой проверки статуса бота.

## Параметры

- `project_id` — number; обязательный параметр.

Точные типы и обязательность берутся из схемы MCP-регистрации. Перед вызовом проверь описание инструмента в MCP-клиенте; не придумывай отсутствующие поля.

## Пример вызова

```json
{
  "tool": "get_project_db",
  "arguments": { "project_id": 42 }
}
```

## Пример успешного ответа

Ответ содержит полный JSON проекта, листы, ноды и связи. Перед изменением сохрани его контекст и не смешивай с устаревшим локальным JSON.

## Типичные ошибки

- Переданы неизвестные или пропущенные обязательные параметры.
- Проект не найден или недоступен текущему MCP-токену.
- Ответ устарел к моменту записи: перечитай проект перед критичным live-патчем.

## Ограничения и безопасность

Тул только читает данные или выполняет проверку; он не должен изменять проект, БД или состояние бота.
- Не трактуй отсутствие ошибки транспорта как подтверждение бизнес-корректности результата.
- Для дальнейшего изменения используй отдельный mutating-тул после проверки данных.

## Связанные инструменты

- `get_tool_docs` — получить карточку этого и связанных тулов.
- `search_tool_docs` — найти подходящие инструменты.
- `get_workflow_docs` — получить рекомендуемую последовательность действий.

## Рекомендуемый следующий шаг

Проверь JSON через `validate_bot_project`, внеси минимальный патч и запиши через `update_project_db` или специализированный `db_update_node`.
