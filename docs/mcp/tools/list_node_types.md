# `list_node_types`

## Назначение

Возвращает типы нод, разрешённые MCP и доступные в палитре конструктора, с кратким описанием. Read-only.

## Когда использовать

Вызывай перед созданием ноды, если не уверен в точном имени типа. Legacy-типы и отключённые типы могут быть отклонены даже если встречаются в старых проектах.

## Параметры

- Инструмент не объявляет именованных параметров.

Точные типы и обязательность берутся из схемы MCP-регистрации. Перед вызовом проверь описание инструмента в MCP-клиенте; не придумывай отсутствующие поля.

## Пример вызова

```json
{
  "tool": "list_node_types",
  "arguments": {}
}
```

## Пример успешного ответа

Ответ — список объектов с типом и описанием. Это каталог, а не полная схема: для полей вызывай `get_node_schema`, для JSON — `get_node_example`.

## Типичные ошибки

- Инструмент не принимает параметры; не передавай `project_id` или `type`.
- Агент использовал отображаемое название вместо машинного типа, например «Текстовое сообщение» вместо `message`.

## Ограничения и безопасность

Тул только читает данные или выполняет проверку; он не должен изменять проект, БД или состояние бота.
- Не трактуй отсутствие ошибки транспорта как подтверждение бизнес-корректности результата.
- Для дальнейшего изменения используй отдельный mutating-тул после проверки данных.

## Связанные инструменты

- `get_tool_docs` — получить карточку этого и связанных тулов.
- `search_tool_docs` — найти подходящие инструменты.
- `get_workflow_docs` — получить рекомендуемую последовательность действий.

## Рекомендуемый следующий шаг

Выбери точный `type`, получи его схему и пример, затем используй `create_node`.
