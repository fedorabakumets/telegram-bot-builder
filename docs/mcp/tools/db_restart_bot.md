# `db_restart_bot`

## Назначение

Перезапустить бот проекта (stop+start). Если token_id не указан — текущий/дефолтный бот; если указан — конкретный токен (для проектов с несколькими токенами). История запусков и UI обновляются в реальном времени автоматически. Запуск асинхронный — после проверь db_bot_status.

## Когда использовать

Используй только по явной просьбе пользователя перезапустить конкретного бота после изменения кода, настроек или проекта. Тул выполняет stop+start асинхронно.

## Параметры

- `project_id` — number; обязательный параметр.
- `token_id` — number; необязательный параметр.

Точные типы и обязательность берутся из схемы MCP-регистрации. Перед вызовом проверь описание инструмента в MCP-клиенте; не придумывай отсутствующие поля.

## Пример вызова

```json
{
  "tool": "db_restart_bot",
  "arguments": { "project_id": 42, "token_id": 7 }
}
```

## Пример успешного ответа

Успешный ответ подтверждает постановку перезапуска, но не завершение старта. После него обязательно вызови `db_bot_status`; при ошибке — `db_bot_logs` или историю запусков.

## Типичные ошибки

- Переданы неизвестные или пропущенные обязательные параметры.
- `project_id` не принадлежит текущему MCP-доступу.
- `token_id` не относится к проекту или бот не настроен.
- Агент сообщил «бот запущен», не проверив `db_bot_status`.

## Ограничения и безопасность

Тул может изменять live-БД, проект или состояние бота. Выполняй его только в рамках явной просьбы пользователя и проверь результат после операции.
- Не перезапускай бота автоматически; перезапуск допустим только по явной просьбе пользователя.
- После операции перечитай состояние и вызови подходящую проверку или логи.
- Если тул требует `confirm`, передавай его только после подтверждения пользователя.

## Связанные инструменты

- `db_bot_status` — проверить фактический статус.
- `db_bot_logs` — найти причину ошибки запуска.
- `db_bot_launch_history` — проверить историю операции.

## Рекомендуемый следующий шаг

Сначала сообщи пользователю, что операция запрошена, затем проверь `db_bot_status`. Не запускай повторный restart, пока первый ещё выполняется.
