# `get_node_example`

## Назначение

Возвращает каноничный пример полной ноды выбранного типа. Используй его как основу для `project.json`, а не придумывай структуру `data` вручную.

## Когда использовать

Вызывай после `get_node_schema`, когда создаёшь новую ноду или не уверен в дефолтных полях. Пример не добавляет ноду в проект и не изменяет данные.

## Параметры

- `type` — string; обязательный параметр.

Точные типы и обязательность берутся из схемы MCP-регистрации. Перед вызовом проверь описание инструмента в MCP-клиенте; не придумывай отсутствующие поля.

## Пример вызова

```json
{
  "tool": "get_node_example",
  "arguments": { "type": "condition" }
}
```

## Пример успешного ответа

Ответ содержит пример с `id`, `type`, `position` и `data`. Замени ID и значения под задачу, сохрани обязательные поля и затем вызови `validate_node`.

## Типичные ошибки

- Переданы неизвестные или пропущенные обязательные параметры.
- Тип не входит в палитру MCP.
- Пример скопирован без замены ID, из-за чего появились дубли.
- Агент добавил собственные поля вместо полей из схемы.

## Ограничения и безопасность

Тул только читает данные или выполняет проверку; он не должен изменять проект, БД или состояние бота.
- Не трактуй отсутствие ошибки транспорта как подтверждение бизнес-корректности результата.
- Для дальнейшего изменения используй отдельный mutating-тул после проверки данных.

## Связанные инструменты

- `get_tool_docs` — получить карточку этого и связанных тулов.
- `search_tool_docs` — найти подходящие инструменты.
- `get_workflow_docs` — получить рекомендуемую последовательность действий.

## Рекомендуемый следующий шаг

Скопируй форму, адаптируй значения, проверь через `validate_node`, затем подключи ноду и проверь проект целиком.
