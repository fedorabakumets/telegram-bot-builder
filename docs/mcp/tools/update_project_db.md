# `update_project_db`

## Назначение

Записывает полный сценарий в live-БД и обновляет открытый холст. Создаёт версию/чекпоинт; адресация идёт по числовому `project_id` из URL редактора.

## Когда использовать

Используй только по явной просьбе изменить live-проект. Перед записью прочитай проект, выполни `validate_bot_project` и передай минимально необходимый JSON.

## Параметры

- `project_id` — number; обязательный параметр.
- `project_json` — union; обязательный параметр.
- `commit_message` — string; необязательный параметр.
- `skip_validation` — boolean; необязательный параметр.

Точные типы и обязательность берутся из схемы MCP-регистрации. Перед вызовом проверь описание инструмента в MCP-клиенте; не придумывай отсутствующие поля.

## Пример вызова

```json
{
  "tool": "update_project_db",
  "arguments": { "project_id": 42, "project_json": { "version": 2, "nodes": [], "edges": [] }, "commit_message": "Обновление сценария" }
}
```

## Пример успешного ответа

Успех означает запись проекта и broadcast на холст. Это не перезапускает бота автоматически; после записи перечитай проект и при отдельной просьбе проверь/перезапусти бота.

## Типичные ошибки

- Переданы неизвестные или пропущенные обязательные параметры.
- JSON не проходит валидацию или содержит битые `target`/дубли ID.
- `project_id` недоступен или проект изменился после чтения.
- `skip_validation` использован без легаси-причины.

## Ограничения и безопасность

Тул может изменять live-БД, проект или состояние бота. Выполняй его только в рамках явной просьбы пользователя и проверь результат после операции.
- Не перезапускай бота автоматически; перезапуск допустим только по явной просьбе пользователя.
- После операции перечитай состояние и вызови подходящую проверку или логи.
- Если тул требует `confirm`, передавай его только после подтверждения пользователя.
