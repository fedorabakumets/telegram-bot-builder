# `db_count_table_rows`

## Назначение

Возвращает количество строк таблицы или количество строк, подходящих под те же фильтры, что и `db_find_table_rows`. Read-only.

## Когда использовать

Используй для проверки объёма данных, пагинации и условий перед массовым изменением. Фильтры не являются SQL.

## Параметры

- `project_id` — number; обязательный.
- `table_id` — number; обязательный.
- `filters` — array из максимум 5 объектов; необязательный.

Точные типы и обязательность берутся из схемы MCP-регистрации. Перед вызовом проверь описание инструмента в MCP-клиенте; не придумывай отсутствующие поля.

## Пример вызова

```json
{
  "tool": "db_count_table_rows",
  "arguments": { "project_id": 42, "table_id": 12, "filters": [ { "column_id": 102, "operator": "filled" } ] }
}
```

## Пример успешного ответа

Ответ содержит число совпавших строк. Сопоставляй его с количеством страниц `db_list_table_rows` перед массовой операцией.

## Типичные ошибки

- Передано больше пяти фильтров или неизвестный оператор.
- `column_id` не принадлежит таблице.
- Агент передал SQL вместо объекта фильтра.

## Ограничения и безопасность

Тул только читает данные или выполняет проверку; он не должен изменять проект, БД или состояние бота.
- Не трактуй отсутствие ошибки транспорта как подтверждение бизнес-корректности результата.
- Для дальнейшего изменения используй отдельный mutating-тул после проверки данных.
