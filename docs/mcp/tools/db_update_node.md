# `db_update_node`

## Назначение

Обновляет ноду по ID в live-БД. Без `sheet_id` ищет по всем листам; если нода не найдена, возвращает ошибку. Создаёт версию проекта.

## Когда использовать

Используй только по явной просьбе изменить live-проект. Сначала перечитай текущую ноду, подготовь минимальный patch и проверь его через `validate_node`. Для локального JSON используй `update_node`.

## Параметры

- `project_id` — number; обязательный параметр.
- `node_id` — string; обязательный параметр.
- `patch` — record; обязательный параметр.
- `sheet_id` — string; необязательный параметр.
- `commit_message` — string; необязательный параметр.

Точные типы и обязательность берутся из схемы MCP-регистрации. Перед вызовом проверь описание инструмента в MCP-клиенте; не придумывай отсутствующие поля.

## Пример вызова

```json
{
  "tool": "db_update_node",
  "arguments": {
    "project_id": 42,
    "node_id": "hello",
    "patch": { "data": { "messageText": "Здравствуйте" } },
    "commit_message": "Обновлён текст приветствия"
  }
}
```

## Пример успешного ответа

Успех подтверждает live-запись и содержит актуальное состояние/версию. После этого перечитай проект и проверь целевые связи.

## Типичные ошибки

- Переданы неизвестные или пропущенные обязательные параметры.
- `node_id` не найден или относится к другому листу.
- Patch нарушает схему ноды или заменяет обязательные поля.
- Проект изменился между чтением и записью.

## Ограничения и безопасность

Тул может изменять live-БД, проект или состояние бота. Выполняй его только в рамках явной просьбы пользователя и проверь результат после операции.
- Не перезапускай бота автоматически; перезапуск допустим только по явной просьбе пользователя.
- После операции перечитай состояние и вызови подходящую проверку или логи.
- Если тул требует `confirm`, передавай его только после подтверждения пользователя.
