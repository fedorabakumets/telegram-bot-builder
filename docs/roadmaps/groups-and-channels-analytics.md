# Аналитика групп и каналов

## Задача

Добавить на вкладку «Аналитика» карточку **«Чаты»**, которая показывает, в скольких группах и каналах присутствует выбранный бот и как это количество меняется со временем.

В одной карточке отображать две серии:

- **Группы** — уникальные обычные группы и супергруппы.
- **Каналы** — уникальные каналы.

Общий график позволяет сравнивать динамику двух типов чатов и занимает меньше места, чем две отдельные карточки. Если позднее для групп и каналов появятся разные подробные показатели, серии можно разделить на самостоятельные карточки.

## Интерфейс

- В заголовке показать текущее количество: «Группы: N · Каналы: N».
- Отображать группы и каналы разными цветами с понятной легендой.
- Поддержать периоды `24ч`, `7д`, `30д`, `12н` и `12м`.
- Добавить режимы **«Всего»** и **«Добавлено за период»**.
- В режиме «Всего» показывать количество доступных чатов на конец каждого временного интервала.
- В режиме «Добавлено за период» показывать число новых чатов внутри каждого интервала.
- В пояснении под графиком показать: «Бот исключён из групп: N · Нет доступа к каналам: N».
- Подсказка «Что это за график?» должна объяснять, что один `chat_id` учитывается только один раз.

Карточка должна использовать выбранные в шапке проект и токен. При переключении бота нельзя показывать данные предыдущего токена.

## Источники данных

Текущее количество считать по уникальным строковым `chat_id` выбранного проекта и токена. Метаданные брать из сохранённого справочника групп и каналов, истории сообщений и сохранённых состояний доступа.

Типы Telegram сопоставлять так:

- `group` и `supergroup` → группа;
- `channel` → канал;
- `private` не участвует в этой карточке.

Сообщения и справочники всегда ограничивать одновременно по `project_id` и `token_id`. Одинаковый Telegram-чат у двух ботов должен считаться отдельно для каждого токена.

## История

По одной текущей истории сообщений нельзя надёжно восстановить прошлое количество чатов: сообщения могли быть удалены, а бот мог быть исключён или повторно добавлен. Для точного графика сохранять ежедневные снимки либо события изменения членства.

Предпочтительный вариант — журнал событий:

- бот добавлен в группу или канал;
- бот исключён;
- бот покинул чат;
- доступ восстановлен;
- тип чата изменился, например группа стала супергруппой.

События получать из Telegram `my_chat_member` и сохранять с проектом, токеном, строковым ID чата, типом, состоянием и временем события. Ежедневную агрегацию можно строить из журнала и хранить отдельно для быстрых длинных графиков.

До накопления истории интерфейс может сразу показать текущие числа. Исторический график начинается с даты выпуска функции; старые точки не следует выдумывать по времени последнего сообщения.

## Доступность чатов

- `available` считается доступным чатом.
- `kicked` и явно сохранённое состояние выхода считаются недоступными.
- `unknown` показывается в текущем количестве, если чат известен, но результат проверки ещё не сохранён; такие строки отдельно учитывать в подсказке.
- `error` не меняет последнее достоверное состояние членства.

Изменение состояния должно обновлять карточку без полной перезагрузки страницы через существующий канал живых событий аналитики.

## Ограничения первой версии

- Учитываются только чаты, которые уже известны выбранному боту.
- Поиск Telegram-чатов вне сохранённых данных не выполняется.
- История до даты запуска функции не восстанавливается.
- Один чат считается один раз независимо от количества участников и сообщений.
- Группы и супергруппы объединены в одну серию.

## Критерии готовности

- Текущие количества групп и каналов совпадают с уникальными чатами выбранного токена.
- Данные двух ботов одного проекта полностью изолированы.
- Исключение и повторное добавление бота меняют состояние и график.
- Повторное событие Telegram не увеличивает счётчик второй раз.
- Переключение периода и режима правильно меняет агрегацию.
- Пустое состояние объясняет отсутствие известных групп и каналов.
- Перезагрузка страницы не теряет накопленную историю.
- Карточка обновляется после события членства без ручного нажатия «Обновить».
- Проверены светлая и тёмная темы, мобильная ширина, длинные числа и отсутствие горизонтального переполнения.
