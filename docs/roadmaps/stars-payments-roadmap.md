# Оплата звёздами Телеграма

План внедрения приёма звёзд в конструкторе. Цифровой товар внутри бота (доступ, подписка, файл, донат) оплачивается **только звёздами**. Карты и сторонние кассы сюда не входят.

Очередь: 🔴 сначала → 🟡 следом → 🟢 по желанию.

---

## Идея одной фразой

Человек на холсте ставит блок «Выставить счёт в звёздах», указывает цену и куда идти **после оплаты**. Бот сам выставляет счёт, сам подтверждает списание и сам продолжает сценарий, когда звёзды пришли.

---

## Как устроена оплата (три момента)

Это не один шаг. На холсте это выглядит как «выставил счёт → заплатили», в работе бота — три разных события:

1. **Выставить счёт** — бот отправляет карточку с кнопкой «Оплатить». Это действие в текущей цепочке (например после `/buy`).
2. **Проверка перед списанием.** Человек нажал «Оплатить». Телеграм ещё **не списывает** звёзды: сначала пишет боту «этот товар ещё продаёте?» и **ждёт ответ не дольше 10 секунд**. Это не пауза в сценарии и не таймер на холсте — это лимит Телеграма. Если бот молчит или отвечает дольше, человеку показывают ошибку, звёзды на месте. Если бот успел сказать «да» — Телеграм списывает звёзды и приходит шаг 3. Отдельный блок на холсте **не ставим**: если в проекте есть хотя бы один счёт, бот сам сразу отвечает «да». Отказ («товара нет») — настройка на самом счёте.
3. **Оплата прошла** — новое событие, не продолжение того же шага. Бот смотрит скрытую метку покупки и ведёт человека на выход «после оплаты».

Выставить счёт **бесплатно**. Звёзды списываются только когда человек нажал «Оплатить».

## Что уже есть

- Тестовый бот по гайду Groosha: `bots/stars_payments_test/` (счёт, проверка, возврат, демо на 1 звезду).
- Узел холста **«Выставить счёт в звёздах»** (`send_invoice`): счёт в чат, `pre_checkout` всегда «да», переход после оплаты (разово; подписка в чат запрещена API).
- Узел холста **«Ссылка на счёт»** (`create_invoice_link`): URL в переменную, переходы после создания и после оплаты, галка подписки на 30 дней.
- Узел холста **«Подписка за звёзды»** (`edit_star_subscription`): отменить / разрешить автопродление по коду покупки.
- Узел холста **«Вернуть звёзды»** (`refund_stars`): `refundStarPayment` по коду покупки, переход после успешного возврата.
- Узел-триггер **«Успешная оплата»** (`successful_payment_trigger`): оплата вне цепочки текущего счёта.
- На холсте уже можно сделать команды «помощь с покупками» и «условия» из обычных блоков: **триггер команды** + **сообщение**. Новых типов для этого не нужно.
- Кнопку «Оплатить» Телеграм рисует сам. Свою клавиатуру у счёта — отдельным заходом.
- Картинка счёта: загрузка / URL / переменная (`invoicePhotoUrl`); `/uploads/` склеивается с `API_BASE_URL`.

## Что блоком не делать


| Задача                             | Как закрывается                                                                          |
| ---------------------------------- | ---------------------------------------------------------------------------------------- |
| Подтверждение «можно списывать»    | Автоматически, если в проекте есть счёт                                                  |
| Помощь с покупками (`/paysupport`) | Триггер команды + сообщение. Телеграм **требует** эту команду у ботов с цифровой оплатой |
| Условия покупки (`/terms`)         | То же самое                                                                              |
| Кнопка «Оплатить»                  | Рисует Телеграм. Своя кнопка — позже, как вид кнопки, не как блок                        |
| Доставка, имя, телефон, карта      | Не для звёзд                                                                             |

## Узлы первой очереди



### 1. Выставить счёт в звёздах ✅ (чат)

Главный блок. Без него остальное не имеет смысла.

**Сделано:** счёт в чат (`send_invoice`) — цена, название, описание, картинка, метка, сохранение суммы/кода, выход **после оплаты**. Глобальный `pre_checkout` всегда «да».

**Ещё нет:** отказ на проверке перед списанием («товара нет»).

**Что делает.** Выставляет счёт в текущий чат. Ссылка на счёт — **отдельный узел** `create_invoice_link` (не режим этого блока).

**Поля (человеку на панели):**


| На панели             | Смысл                                                                                              |
| --------------------- | -------------------------------------------------------------------------------------------------- |
| Название              | Заголовок карточки, 1–32 знака                                                                     |
| Описание              | Текст под названием, 1–255 знаков                                                                  |
| Цена                  | Целое число звёзд, один пункт                                                                      |
| Картинка              | По желанию                                                                                         |
| Скрытая метка покупки | По умолчанию = номер блока. Нужна, чтобы понять, какой товар оплатили. Можно подставить переменную |
| Куда сохранить        | Сумма, код покупки — чтобы потом вернуть звёзды                                                    |
| Как выставить         | В чат ✅; ссылка — узел «Ссылка на счёт» ✅                                                         |
| Подписка на 30 дней   | **Только у ссылки** ✅. В чат Telegram запрещает (`SUBSCRIPTION_EXPORT_MISSING`)                    |
| Отказать, если…       | Позже: товар кончился / человек уже купил. Иначе проверка перед списанием всегда «да»              |


**Выходы:**

- **После отправки** — редко (лог, «счёт выставлен»).
- **После оплаты** — основной: выдать доступ, записать в таблицу, написать «спасибо».

Скрытая метка по умолчанию совпадает с номером блока. Когда приходит успешная оплата, сценарий идёт на второй выход этого же блока.

**Типичная цепочка:**

```
триггер команды /buy
  → выставить счёт в звёздах (100 звёзд)
        после оплаты → записать переменную
                     → сообщение «оплата прошла»
```

---



### 1b. Ссылка на счёт ✅

**Сделано:** узел `create_invoice_link` — Bot API `createInvoiceLink`, URL в переменную, сразу `autoTransitionTo`, после оплаты `afterPaymentTo` / триггер «Успешная оплата», галка `invoiceSubscription` (**единственный** способ подписки: в чат Telegram отвечает `SUBSCRIPTION_EXPORT_MISSING`). Общий `_stars_payment_targets` и `pre_checkout` с `send_invoice`.

**Типичная цепочка:**

```
триггер команды /buy
  → ссылка на счёт
        ссылка готова → сообщение с URL
        после оплаты → доступ
```

---

### 2. Вернуть звёзды ✅

**Сделано:** узел `refund_stars` — возврат по коду покупки (`refundStarPayment`), кому (текущий / custom), `ignoreErrors`, выход после успешного возврата.

**Что делает.** Возвращает звёзды человеку по **коду покупки** (тот самый код после успешной оплаты и в разделе «Звёзды» в Телеграме).

Возврат возможен **только в том боте**, где человек платил. Чужие покупки этим блоком не вернуть.

**Поля:** кому вернуть (этот человек или из переменной) и код покупки (ввод или переменная).

**Зачем нужен сразу после счёта.** Телеграм требует возможность помочь с покупкой. Без возврата магазин неполный.

**Цепочка:**

```
триггер команды /refund
  → ввод кода
  → вернуть звёзды
  → сообщение «звёзды снова у вас»
```

---



### 3. Успешная оплата ✅

**Сделано:** узел `successful_payment_trigger` — фильтр метки (`all` / `exact` / `starts_with`), сохранение суммы и кода, переход. Общий роутер `successful_payment`: сначала счёт (`_stars_payment_targets`), иначе триггер.

**Что делает.** Срабатывает, когда оплата пришла, а счёт выставляли **не в этой цепочке**: ссылка из канала, рассылка, другой блок / после рестарта.

У «Счёта в звёздах» уже есть выход «после оплаты» — его хватает в большинстве магазинов. Этот блок закрывает случаи «заплатили по ссылке, которую отправили вчера».

---



### 4. Платёж вернули 🟡

**Что делает.** Телеграм сообщил, что оплату отменили или вернули (спор, возврат со стороны магазина звёзд и т.п.).

**Зачем.** Снять доступ, иначе товар останется у человека, а звёзд уже нет.

**Поля:** фильтр по метке, куда сохранить код, куда перейти (забрать роль, написать «доступ закрыт»).

---



### 5. Подписка за звёзды ✅

**Сделано:** узел `edit_star_subscription` — `editUserStarSubscription`: отменить (`subscriptionAction: cancel`) или снова разрешить (`enable`) автопродление по коду покупки. Выходы: успех / пустой код / ошибка.

**Что делает.** Управление уже купленной подпиской (ссылка с `invoiceSubscription`). Возврат денег — по-прежнему `refund_stars`.

## Узлы по желанию

Не счета, но тоже звёзды. Делать после магазина, если понадобится.

### 6. Баланс звёзд 🟢

Сколько звёзд сейчас на боте. Нужно перед выводом и чтобы понять, хватит ли на возврат.

### 7. История звёзд 🟢

Список операций для админки: кто платил, возвраты, списания.

### 8. Платное медиа 🟢

Фото или видео, которое открывается за звёзды. Это не счёт и не кнопка «Оплатить» в чате с товаром.

### 9. Купили платное медиа 🟢

Сработало после такой покупки. Выдать подпись, записать факт покупки.

Подарки, платная рассылка, платная подписка на чат — тоже звёзды, но **другая тема**. В этот план не входят.

## Как проверить, не тратя звёзды насовсем

- Отправить счёт можно даром — карточка появится без списания.
- Нажать «Оплатить» в обычном Телеграме нельзя без звёзд на аккаунте.
- Для живой проверки: команда «демо» на 1 звезду с **мгновенным возвратом** (как в тестовом боте). Звезда уходит и возвращается целиком, с этой операции Телеграм долю не держит.
- Есть отдельная копия Телеграма для разработчиков (свой аккаунт, свой бот). Там оплата не настоящая. Обычный бот туда не переносится.

На холсте только русские названия. В схеме проекта типы такие:


| На холсте            | Тип в проекте                  |
| -------------------- | ------------------------------ |
| Выставить счёт в звёздах | `send_invoice`             |
| Ссылка на счёт       | `create_invoice_link`          |
| Вернуть звёзды       | `refund_stars`                 |

| Платёж вернули       | `refunded_payment_trigger`     |
| Баланс звёзд         | `get_star_balance`             |

| Купили платное медиа | `paid_media_purchased_trigger` |


Режим подписки на 30 дней — поле `invoiceSubscription` **только** у «Ссылка на счёт» (✅). У «Выставить счёт» Telegram запрещает (`SUBSCRIPTION_EXPORT_MISSING`). Управление автопродлением — `edit_star_subscription` (✅).
