# Активность сообщений по типам чатов

## Задача

Расширить карточку **«Активность сообщений»** на вкладке «Аналитика», чтобы пользователь мог отдельно анализировать переписку в личных чатах, группах и каналах.

Основные категории:

- **Все** — сумма учитываемых сообщений во всех типах чатов.
- **Личные** — сообщения между пользователями и ботом в личных диалогах.
- **Группы** — сообщения обычных групп и супергрупп.
- **Каналы** — сообщения и публикации каналов.

Сообщения других Telegram-ботов являются признаком отправителя, а не типом чата. Для них предусмотреть дополнительный фильтр **«От ботов»**, который можно применять к группам и другим подходящим категориям.

## Интерфейс

Добавить в карточку переключатель **«Все / Личные / Группы / Каналы»**. Существующий выбор направления сообщений сохранить как независимую настройку:

- все направления;
- входящие;
- исходящие.

Пользователь должен иметь возможность совместить настройки, например посмотреть только исходящие сообщения в группах или входящие сообщения в личных чатах.

В режиме «Все» использовать составные столбцы или несколько цветных серий, чтобы показать вклад каждого типа чата. Легенда должна позволять временно скрывать отдельные серии. При выборе одного типа показывать обычный график без лишнего цветового разделения.

Выбранные настройки хранить локально для карточки. При смене проекта или бота данные предыдущего токена не должны оставаться на графике.

## Правила подсчёта

- `private` относится к личным сообщениям.
- `group` и `supergroup` объединяются в группы.
- `channel` относится к каналам.
- Один сохранённый экземпляр сообщения учитывается один раз.
- Направление определяется существующим полем входящего или исходящего сообщения.
- Записи с `message_type = system`, включая блокировку и разблокировку бота, не входят в активность сообщений.
- Технические повторы Telegram и повторно обработанные обновления не должны увеличивать показатели.
- Все выборки ограничиваются одновременно по `project_id` и `token_id`.

Фильтр «От ботов» использует сохранённый признак отправителя `is_bot`. Сообщения текущего бота по-прежнему относятся к исходящим и не смешиваются с входящими сообщениями других ботов.

## Короткие и длинные периоды

Короткие периоды можно рассчитывать по сохранённой истории сообщений с группировкой по времени, типу чата и направлению.

Для длинных периодов расширить дневные агрегаты активности. В каждой агрегированной строке должны быть доступны:

- проект;
- токен;
- дата UTC;
- тип чата;
- направление;
- признак отправителя-бота для входящих сообщений;
- количество сообщений.

Миграция не должна приписывать старым агрегатам выдуманный тип чата. Исторические данные без детализации можно показывать только в режиме «Все» и визуально обозначать как **«Тип чата неизвестен»**. Новая детализация накапливается с момента выпуска функции.

## API

Эндпоинт аналитики принимает необязательные фильтры:

- `chat_kind`: `all`, `private`, `groups` или `channels`;
- `direction`: `all`, `incoming` или `outgoing`;
- `sender_kind`: `all`, `users` или `bots`.

Ответ для режима `all` содержит отдельные серии по типам чатов и общий итог. Сервер валидирует сочетания фильтров и не возвращает внутренние идентификаторы или содержимое сообщений.

## Живые обновления

Новое сообщение обновляет только соответствующую серию выбранного проекта и токена. Клиент применяет событие, если оно подходит под текущие фильтры карточки. При переключении фильтра выполняется загрузка подходящей агрегации с сервера, чтобы не полагаться только на данные текущей вкладки.

## Ограничения первой версии

- Группы и супергруппы показываются одной категорией.
- Системные события не учитываются.
- Текст и медиасодержимое сообщений не анализируются.
- Старые дневные данные без типа чата доступны только в общей серии.
- Фильтр «От ботов» зависит от сохранённого признака отправителя и не пытается заново получать профиль через Telegram.

## Критерии готовности

- Сумма личных, групповых и канальных серий совпадает с общей активностью за период.
- Входящие и исходящие сообщения правильно разделяются внутри каждой категории.
- Системные записи не изменяют показатели.
- Сообщение другого бота определяется отдельно от исходящего сообщения текущего бота.
- Данные проектов и токенов изолированы.
- Короткие интервалы совпадают с сохранённой историей сообщений.
- Длинные интервалы используют новые дневные агрегаты.
- Старые недетализированные значения не выдаются за личные или групповые.
- Живое сообщение обновляет правильную серию без полной перезагрузки.
- Переключатели не вызывают горизонтального переполнения на мобильной ширине.
- Проверены светлая и тёмная темы, пустые состояния и большие значения.
