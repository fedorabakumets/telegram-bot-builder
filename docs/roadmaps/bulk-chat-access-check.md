# Массовая проверка доступов пользователей

Реализовано. Описание для людей и контракт API: [docs/features/bulk-chat-access-check.md](../features/bulk-chat-access-check.md).

## Задача

В карточке «Всего пользователей» на вкладке «Аналитика» добавить кнопку **«Проверить доступы»** рядом со строкой «Заблокировали / Аккаунт удалён». Она запускает повторную проверку всех личных диалогов выбранного бота и обновляет сохранённые статусы пользователей.

Название «Проверить доступы» точнее, чем «Проверить всех»: пользователю сразу понятно, какое действие будет выполнено.

## Поведение интерфейса

- Перед запуском показать число пользователей, которые попадут в проверку.
- Во время работы показывать прогресс: «Проверено 48 из 174».
- Заблокировать повторный запуск, пока текущая задача не завершена.
- Дать возможность отменить оставшуюся часть проверки.
- Разрешить закрыть или перезагрузить страницу: серверная задача должна продолжаться в фоне.
- После возврата на страницу восстановить текущий прогресс.
- По мере получения результатов обновлять показатели «Заблокировали» и «Аккаунт удалён».
- После завершения показать итог, например: «Доступны: 168 · Заблокировали: 4 · Ошибки: 2».
- Повторно проверять пользователей с сохранённым статусом блокировки, поскольку они могли разблокировать бота.

Рядом с кнопкой нужна подсказка: **«Во время проверки пользователь может на несколько секунд увидеть статус “печатает…” от бота. Сообщения отправлены не будут»**.

## Серверная обработка

Проверку выполнять фоновой задачей небольшими пакетами. Последовательную отправку запросов ограничить по скорости, чтобы не создавать резкий всплеск обращений к Telegram API.

Для каждого пользователя сервер:

1. Выполняет фактическую проверку через Telegram `sendChatAction`.
2. Классифицирует результат как `available`, `kicked` или `error`.
3. Сохраняет статус и время проверки в `chat_access`.
4. Синхронизирует `bot_users.is_blocked`.
5. Публикует обновление прогресса для интерфейса.

Ошибки отдельных пользователей не должны останавливать всю задачу. Секреты Telegram, внутренние ответы API и технические тексты исключений нельзя возвращать в браузер.

## Состояния задачи

- `pending` — задача создана и ожидает запуска.
- `running` — проверка выполняется.
- `cancelling` — получен запрос на отмену, завершается текущая операция.
- `cancelled` — оставшиеся пользователи не проверяются.
- `completed` — все пользователи обработаны.
- `failed` — задача не может продолжаться из-за общей ошибки.

Хранить идентификатор проекта, токена, состояние, общее и обработанное количество, итоговые счётчики, время начала и завершения. Одновременно для одной пары проекта и токена разрешать только одну активную задачу.

## Ограничения первой версии

- Проверяются только личные диалоги выбранного бота.
- Группы и каналы в массовую проверку не входят.
- Проверка не отправляет сообщения, но `sendChatAction` может кратко показать индикатор «печатает…».
- Результат отражает доступность на момент запроса и со временем может устареть.
- Автоматические события `my_chat_member` остаются основным способом оперативно узнавать о новых блокировках и разблокировках; массовая проверка нужна для сверки старых и пропущенных состояний.

## Критерии готовности

- Кнопка отображается только при выбранном боте и наличии пользователей.
- Двойное нажатие не создаёт две задачи.
- Прогресс восстанавливается после перезагрузки страницы.
- Отмена останавливает обработку оставшейся очереди.
- Счётчики аналитики обновляются без полной перезагрузки вкладки.
- Повторная проверка снимает блокировку с пользователя, который разблокировал бота.
- Ошибка одного запроса учитывается в итогах и не прерывает очередь.
- Смена выбранного бота показывает состояние его задачи и не смешивает результаты.
- Проверены светлая и тёмная темы, узкая ширина и длинные значения прогресса.
