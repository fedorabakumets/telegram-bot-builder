# Запуск исполнителя при обновлении Railway

Контейнеры с одинаковым `RUNNER_ID` используют одну аренду Redis. Новый
контейнер ожидает её освобождения до 120 секунд с повтором раз в секунду.
Ожидание не удаляет и не перехватывает действующую аренду. Чтение команд и
запуск воркеров начинаются только после получения аренды.

Это позволяет предыдущему контейнеру завершиться во время обновления Railway,
не исчерпывая попытки перезапуска нового контейнера. При занятой аренде сообщение
об ожидании выводится один раз. Если старый процесс остаётся активным дольше
двух минут, новый завершает запуск с ошибкой; второй исполнитель не запускается.

`SIGTERM` и `SIGINT` отменяют ожидание, включая зависший запрос Redis.
Если ответ о захвате приходит после отмены, освобождается только собственная
аренда. Ошибка Redis не маскируется сообщением о занятом исполнителе.

Адресные проверки: `npx vitest run --config server/runner/vitest.config.ts`.
Они подключены к заданию `runtime` в CI `Split runtime`.
