# Диагностика и восстановление общего обработчика

## Что изменилось

Неожиданное завершение общего Python передаётся как отдельное служебное событие
`worker_host_crash` перед событиями завершения его ботов. Причина содержит исходные
код выхода и сигнал, PID и доступные числовые показатели cgroup. Счётчик OOM относится
ко всему контейнеру: его увеличение само по себе не доказывает убийство конкретного PID.
Подобное событие из stdout дочернего процесса отбрасывается: его создаёт Node.

Уровень Python logging передаётся отдельно. Предупреждения сохраняются в журнале,
но не становятся причиной завершения бота. Ошибка общего процесса имеет приоритет
перед старым stderr; подтверждённый отказ Telegram сохраняет запрет запуска.
На холсте используется нейтральная подпись «Бот завершился с ошибкой».

Восстановление инфраструктуры отдельно от настройки автоперезапуска ошибок бота:
подтверждённая авария общего обработчика позволяет восстановить `desiredStatus=running`
при `autoRestart=0`. Очередь и резервная сверка используют единый ограниченный бюджет
попыток, задержки и одну отложенную попытку на токен. После неудачной попытки
инфраструктурное восстановление продолжает backoff до лимита. Ручная остановка,
смена поколения, shutdown, заморозка и недействительный токен запрещают повтор.
Счётчики попыток, как и ранее, хранятся в памяти backend.

Изменения не исправляют старые записи истории задним числом и не снижают потребление
памяти сценариев. Для проверки нового механизма на проде нужен выпуск backend и runtime.

## Замер production 15 ноября 2026 года

Проверялась действующая версия production без этих локальных исправлений.
Лимит контейнера не менялся: 349 999 104 байта, примерно 350 МБ.
До проверки боты #5 проекта 9 и #11 проекта 13 были остановлены; через штатный API
их запустили последовательно. Токены и настройки автоперезапуска не менялись.

| Состояние | Память контейнера, десятичные МБ |
|---|---:|
| До запуска, общий Python отсутствует | 168–171 |
| После запуска #5 «Обменники» | 296–298 |
| После запуска обоих, окно около трёх минут | 306–309 |

С обоими ботами RSS общего Python составлял около 134 МБ; файловый кеш контейнера —
около 109 МБ. Счётчик `oom_kill` оставался равным 2: новых убийств не зафиксировано.
Запас до лимита — около 41 МБ в этом окне. Это короткий замер после запуска,
а не доказательство отсутствия роста в течение суток или безопасности пиков.
У #5 включена Telethon-интеграция, поэтому удержание постоянного Python ожидаемо.

## Проверки исправления

- Сверка состояния: 7 тестов; планировщик и защитные условия: 18 тестов.
- Обработка завершения и авторизации: 12 тестов.
- Общий обработчик на Windows: 17 успешных тестов, один POSIX-тест пропущен.
- Независимая интеграция на Linux WSL: 4 теста, включая сигнал завершения.
- Сторож реального Python на Linux: 2 теста, SIGTERM/SIGKILL и ненулевой код.
- Диагностика и счётчики: адресные тесты; UI: 6 тестов; Python logging: один тест.
- Сборки frontend, backend и runtime выполнены успешно.

Локальная диагностика TypeScript не проводилась: getDiagnostics отсутствует.
Полные check/tsc не запускались по правилам репозитория. Сборка и тесты не заменяют
проверку типов; её результат для будущего коммита следует проверить в CI.
