# Запросы с пользовательской и административной cookie

Изменяющие запросы к `/api` и `/admin/api` проверяют источник, если сервер распознал
пользовательскую сессию или действующую `admin_auth`. Методы GET, HEAD и OPTIONS
не требуют этой проверки. Права пользователя и авторизация проверяются отдельно.

Браузер отправляет `Origin` автоматически. Он должен точно совпадать с публичным
адресом панели, включая протокол и порт. При отсутствии `Origin` сервер принимает
`Referer` с тем же адресом. Если `Origin` передан, неправильный `Origin` нельзя
отменить правильным `Referer`, Bearer-токеном или дополнительным заголовком.
`Origin: null` не допускается.

В разделённом режиме панель и API доступны браузеру через один адрес: frontend
проксирует API, сохраняя исходный Host. Telegram Mini App использует Origin
загруженной панели; разрешать вместо него `web.telegram.org` не нужно.
Политика cookie `SameSite=None` сохраняется для совместимости с Mini App.

## Клиенты вне браузера

API-клиент с cookie может явно отправлять `Origin: https://адрес-панели`.
Если нет ни Origin, ни Referer, допускаются следующие варианты:

- `Content-Type: application/json` для обычного JSON-запроса;
- `X-Botcraft-CSRF: 1` для формы, multipart-загрузки или другого содержимого.

Эти варианты доступны только без браузерных заголовков `Sec-Fetch-Site`,
`Sec-Fetch-Dest` и `Sec-Fetch-User`. Один `Sec-Fetch-Mode`, который выставляет
также Node.js fetch, не считается признаком браузера.

Защита опирается на отсутствие разрешающего credentialed CORS для чужих origin:
браузерная JSON-отправка или специальный заголовок потребуют успешного preflight.
При добавлении CORS эту модель безопасности необходимо пересмотреть.

Bearer-клиент без пользовательской или административной cookie продолжает
использовать прежнюю авторизацию. Наличие Bearer вместе с действующей cookie
не отменяет проверку источника. Отказ возвращает HTTP 403 и
`{"error":"CSRF_ORIGIN_MISMATCH"}`.

## Машинные интеграции

Следующие маршруты сохраняют собственную авторизацию и не используют cookie-CSRF:

- `/api/auth/agent/telegram` и `/api/auth/agent/disconnect` — подпись агента;
- `/api/runtime/media`, `/api/runtime/media/incoming-photo` и
  `/api/runtime/media/invoice-link` — авторизация runtime;
- `/api/webhook/:projectId/:tokenId` — существующая проверка webhook;
- `/api/hooks/:projectId/*` — существующая обработка публичных HTTP hooks.

Исключения не предоставляют права доступа и не распространяются на остальные
маршруты `/api/auth` или `/api/runtime`.
