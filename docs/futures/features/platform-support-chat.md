# Чат поддержки платформы BotCraft

> Переписка между пользователями конструктора и администратором прямо в интерфейсе,
> с мостом в Telegram-группу с темами.

---

## Принятые решения

| Вопрос | Решение |
|--------|---------|
| Откуда отвечает оператор | Из админки `/admin/support` и из Telegram-группы с темами |
| Модель диалога | Один непрерывный чат на пользователя со статусом «открыт / закрыт» |
| Кто может писать | Только авторизованные через Telegram (гости не видят кнопку) |
| Операторы | Один администратор, без назначения и распределения |
| Бот для моста | Отдельный служебный бот поддержки, не бот входа |

## Модель данных

### `support_threads` — один диалог на пользователя

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | serial | Первичный ключ |
| `user_id` | bigint, unique | Ссылка на `telegram_users.id` |
| `status` | text | `open` / `closed` |
| `unread_by_admin` | integer | Сколько сообщений пользователя не прочитал админ |
| `unread_by_user` | integer | Сколько ответов не прочитал пользователь |
| `telegram_topic_id` | integer, null | ID темы в группе поддержки (этап 3) |
| `last_message_at` | timestamp | Время последнего сообщения — сортировка списка |
| `created_at` | timestamp | Дата создания |

### `support_messages` — сообщения

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | serial | Первичный ключ |
| `thread_id` | integer | Ссылка на `support_threads.id` |
| `sender` | text | `user` / `admin` |
| `text` | text | Текст до 4000 символов |
| `context` | jsonb, null | Проект, страница, браузер в момент отправки |
| `source` | text | `web` / `telegram` — откуда пришёл ответ |
| `created_at` | timestamp | Дата создания |

Правила:
- Сообщение пользователя увеличивает `unread_by_admin` и переоткрывает закрытый диалог.
- Ответ админа увеличивает `unread_by_user`.
- Открытие чата обнуляет счётчик своей стороны.

## API

### Пользователь (`/api/support/*`, под глобальным `requireApiAuth`)

| Метод | Путь | Описание |
|-------|------|----------|
| GET | `/api/support/thread` | Свой диалог и сообщения (диалог может отсутствовать) |
| POST | `/api/support/messages` | Отправить сообщение `{ text, context? }` |
| POST | `/api/support/read` | Отметить ответы прочитанными |

### Админ (`/admin/api/support/*`, под `requireAdminAuth`)

| Метод | Путь | Описание |
|-------|------|----------|
| GET | `/admin/api/support/threads?status=open\|closed\|all` | Список диалогов |
| GET | `/admin/api/support/threads/:id` | Диалог с сообщениями и профилем пользователя |
| POST | `/admin/api/support/threads/:id/messages` | Ответить `{ text }` |
| POST | `/admin/api/support/threads/:id/read` | Отметить прочитанным |
| PATCH | `/admin/api/support/threads/:id` | Сменить статус `{ status }` |

## Этапы

### Этап 1 — минимальная версия
- [x] Таблицы, миграция в `init-db`, SQL-файл `migrations/0019_create_support_tables.sql`
- [x] Общие типы `shared/support/support.types.ts`
- [x] Серверный слой `server/support/`: репозиторий, DTO, валидация, хендлеры, роуты
- [x] Кнопка «💬» в шапке редактора со счётчиком и выезжающая панель чата
- [x] Страница `/admin/support`: список диалогов и переписка, пункт в боковом меню
- [x] Обновление опросом (пользователь — 10 с при открытой панели, 30 с в фоне; админ — 10 с)

### Этап 2 — реальное время
- [x] Событие `support:message` через WebSocket `/api/support/ws` и `/admin/api/support/ws` вместо опроса
- [x] События `support:read` и `support:status`, отметка «Прочитано» у последнего своего сообщения
- [x] Redis-канал `platform:support_event`: реплика публикует событие, остальные делают локальный fan-out. Своя публикация пропускается по `originInstanceId`. Без Redis остаётся рассылка только на текущей реплике
- [x] Запасной опрос раз в 30 секунд, пока сокет не открыт

### Этап 3 — мост в Telegram
- [ ] Настройки в админке: токен служебного бота и ID группы с темами
- [ ] Первое сообщение пользователя создаёт тему «Имя @username», пишем `telegram_topic_id`
- [ ] Ответ в теме сохраняется с `source = telegram` и приходит в веб-чат
- [x] Уведомление пользователю в личку, если он запускал служебного бота. Токен хранится в `app_settings` (`support_bot_token`). В чате и в админке написано, что ответ придёт в Telegram. Сообщение пользователя уходит в личку администраторам из `SUPPORT_ADMIN_CHAT_IDS` (`app_settings.support_admin_chat_ids`).

Ограничение Telegram: бот не может первым написать человеку, который не нажимал Start.
Поэтому личные уведомления работают только для тех, кто запускал служебного бота.
