# 📋 Release Notes v2.2.1.4

**Дата выпуска:** 2 октября 2026 г.

Накопительный релиз с `v2.1.9.8` (промежуточных GitHub Release / тегов на линейке `2.2.x` не было). Сравнение: [v2.1.9.8…v2.2.1.4](https://github.com/fedorabakumets/telegram-bot-builder/compare/v2.1.9.8...v2.2.1.4).

---

## 🔥 Главное в этом релизе

### Изоляция окружения ботов

Боты больше не наследуют `process.env` сервера. Подстановка `${{VAR}}` только из `WORKER_ENV_PASSTHROUGH` вне denylist; API `/api/server/env-keys` отдаёт реально доступные ключи. В одном процессе воркера боты не видят env друг друга.

### Безопасный `psql_query` и флаг builtin

Плейсхолдеры `{имя}` уходят в параметры asyncpg (`$n`), а не вклеиваются в SQL. Builtin к БД платформы — только при `PSQL_BUILTIN_ENABLED` (по умолчанию `false`); UI не показывает `DATABASE_URL` платформы без разрешения.

### Исполнитель ботов и Railway

Режимы `WORKER_RUNTIME` (process / docker / remote), `npm run runner`, образ `Dockerfile.runner`, команды через Redis Streams, отдельные сервисы ботов на Railway, группировка `WORKER_GROUPING`.

### Хранилище сборок и загрузок

Сборки ботов в storage (`BOT_ARTIFACT_SOURCE=storage`), перенос между бакетами, раздача `/uploads` с fallback из S3. Env бота из БД/команды (`BOT_ENV_SOURCE=inline`) без правки `.env` в роутах.

## 🔒 Безопасность

- **Env ботов** — воркер и процесс бота получают только базовое окружение без секретов сервера
- **`WORKER_ENV_PASSTHROUGH` + denylist** — политика серверных переменных во всех режимах runtime; `ALLOWED_SERVER_ENV_KEYS` удалён
- **`${{VAR}}`** — подстановка только из разрешённого списка
- **`/api/server/env-keys`** — только ключи, которые реально можно пробросить
- **Обёртка `os.environ` в worker.py** — изоляция env между ботами в одном процессе
- **`psql_query`** — `{имя}` → параметры asyncpg; без склейки SQL-строки
- **`PSQL_BUILTIN_ENABLED`** — по умолчанию выключен; опция `psqlBuiltinEnabled` и проверка строки подключения
- **UI psql_query** — `DATABASE_URL` платформы скрыт без разрешения администратора
- **Рассылка** — получатели только своего `project_id` + `token_id`
- **Shutdown** — один проход на SIGTERM, без падения на повторном `pool.end()`
- **Userbot** — session string не попадает в логи; PUT `/userbot` не стирает сохранённые session/API Hash

## 📦 Хранилище и артефакты

- Раздача `/uploads` с запасным чтением из S3, s3-proxy и перенос uploads в бакет (`UPLOADS_STORAGE_ID`)
- Сборки ботов в хранилище (`BOT_ARTIFACT_SOURCE=storage`)
- Перенос сборок между хранилищами (`npm run bot-builds:move`)
- Том для `.bot-builds` в docker-compose
- **`BOT_ENV_SOURCE=inline`** — сборка env из БД и передача в воркер/команду start без правки файла `.env` в роутах; настройки токена и `ADMIN_IDS` меняют только БД

## 🚂 Исполнитель ботов и Railway

- **`WORKER_RUNTIME=process`** — локальный/встроенный запуск (как раньше)
- **`WORKER_RUNTIME=docker`** — воркер в контейнере без окружения сервера; кэш байткода в копии папки бота
- **`WORKER_RUNTIME=remote`** — панель отдаёт воркеры исполнителю через Redis Streams
- **`npm run runner`** + **`Dockerfile.runner`** — образ исполнителя в GHCR (amd64/arm64, BuildKit-кеш)
- Исполнитель скачивает код бота из S3, отвечает на ping/hello, переиспользуется при перезапуске
- Боты проекта в отдельном сервисе Railway (`WORKER_RAILWAY_PROJECTS`), регион `RAILWAY_REGION`, остановка через `deploymentRemove`
- Переменные `RAILWAY_BOT_*` для адресов БД и Redis; площадка по `RAILWAY_REPLICA_ID`
- **`WORKER_GROUPING`** — режимы `shared` (один воркер на все проекты) и `owner` (воркер на владельца)
- Ленивая сборка моделей pydantic/aiogram и компиляция байткода вне воркера
- Образ Cursor self-hosted worker (My Machines) для Railway
- `npm run site:create` — площадка в аккаунте Railway по токену пользователя

## 🏗️ Образ панели и деплой

- Образ панели на **Node 22** alpine
- BuildKit cache mounts для npm и pip; **`npm ci`** вместо `npm install` (`.npmrc` с legacy-peer-deps)
- SQL-миграции при старте сервера (убран `npm run migrate` из start/dev)
- Один конфиг Railway — `railway.toml` (без `buildCommand` и `[env]`); `railway.json` удалён
- Деплой на VPS через GitHub Actions + GHCR; ожидание `/api/health` после recreate
- Предсказуемое восстановление ботов после деплоя: Redis → параллельно по проектам, retry, защита от OOM

## 🐛 Исправления

- Рассылка не пересекает аудиторию других проектов/токенов
- Повторный SIGTERM больше не роняет процесс на `pool.end()`
- Сохранение сценария перезапускает всех запущенных ботов проекта
- `user_activity_daily` — корректный `user_id` (int) и бэкфилл миграцией 0018
- Легенда активности — уникальные пользователи за период, не сумма дней
- Admin cookie: не ставить `Secure` при входе по HTTP
- `tokens/parse` — 400 на невалидный token вместо 500
- Перетаскивание кнопок клавиатуры пальцем на мобильных
- Дублирующийся ключ `ignoreErrors` в `nodeSchema`
- Отображение строки переменной в UI env (закрытие внешнего `div`)
