# Сборки ботов в хранилище

Сгенерированный код бота можно хранить не только в папке `bots/` на диске панели, но и в хранилище (локальная приватная папка или S3). Это первый шаг к запуску ботов отдельно от панели: исполнителю на другой машине не нужен диск панели, чтобы получить код.

## Как включить

```env
BOT_ARTIFACT_SOURCE=storage
# Необязательно:
BOT_BUILDS_STORAGE_ID=    # ID из storage_configs; пусто — приватная папка
BOT_BUILDS_DIR=.bot-builds
BOT_BUILDS_KEEP=3
```

По умолчанию `BOT_ARTIFACT_SOURCE=disk` — всё работает как раньше.

## Что происходит

1. При запуске бота панель считает отпечаток генерации: данные проекта, настройки токена, версия генератора (`.generated-code.json`).
2. Если сборки с таким отпечатком ещё нет, код `.py` сжимается gzip и записывается в хранилище по ключу `bot-builds/<projectId>/<tokenId>/<fingerprint>.py.gz`, затем добавляется строка в таблицу `bot_builds` (размер, sha256, версия генератора).
3. При авто-восстановлении ботов (перезапуск сервера, автоперезапуск) панель сначала смотрит на папку `bots/`. Если её нет или код устарел, а в хранилище есть сборка с тем же отпечатком — код скачивается, проверяется по sha256 и кладётся на диск без повторной генерации.
4. На каждый токен хранится не больше `BOT_BUILDS_KEEP` последних сборок, старые удаляются вместе с объектами.

Ручной запуск из панели по-прежнему всегда генерирует код заново — так же, как и без сборок.

## Что попадает в сборку

Только сгенерированный `.py`. Токен, `DATABASE_URL`, userbot-сессия и другие значения `.env` в сборку **не попадают** — `.env` по-прежнему собирается из базы при каждом запуске.

## Какое хранилище выбрать

- **Пусто (`BOT_BUILDS_STORAGE_ID` не задан)** — приватная папка `BOT_BUILDS_DIR` (`.bot-builds/`). Она не раздаётся по HTTP. Подходит для одного сервера. В `docker-compose` папку нужно примонтировать томом (как `./bots`), иначе сборки пропадут при пересоздании контейнера.
- **S3 / MinIO** — создайте хранилище в настройках (`storage_configs`) и укажите его ID. Бакет должен быть **приватным**: в сборке весь код бота.

Хранилище `local-default` (папка `uploads/`) для сборок не используется: она раздаётся публично по `/uploads/...`. Если указанное хранилище не найдено, сборка не сохраняется, а в логе появляется предупреждение.

## Отказоустойчивость

Ошибки хранилища не мешают запуску бота: при сбое записи или чтения панель пишет предупреждение `[BotBuilds]` в лог и работает по-старому (генерация и запуск с диска). Повреждённая сборка (не совпал sha256) не используется.

## Ограничения текущей версии

- `.env` и медиа (`uploads/`) по-прежнему на диске панели.
- Боты запускаются той же панелью; отдельные исполнители — следующий шаг.
- При удалении токена или проекта строки `bot_builds` удаляются каскадно, а объекты в хранилище остаются — их можно удалить по префиксу `bot-builds/<projectId>/`.
