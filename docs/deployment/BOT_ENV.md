# Переменные бота без файла .env

Переменные бота (токен, `ADMIN_IDS`, `DATABASE_URL`, userbot-сессия, свои переменные токена) можно не хранить в файле `bots/<папка>/.env`, а собирать из базы при каждом запуске и передавать воркеру прямо в команде запуска. Вместе со [сборками в хранилище](BOT_BUILDS.md) это убирает зависимость бота от диска панели: исполнителю на другой машине достаточно кода из хранилища и команды запуска.

## Как включить

```env
BOT_ENV_SOURCE=inline
```

По умолчанию `BOT_ENV_SOURCE=file`: `.env` пишется в папку бота при каждом запуске, как раньше.

## Что происходит

1. При запуске панель собирает текст `.env` из БД: настройки токена, `bot_projects.admin_ids`, переменные токена, `DATABASE_URL`/`REDIS_URL` панели, userbot (если включён). Текст тот же, что попал бы в файл, байт в байт.
2. В режиме `inline` текст разбирается в словарь и уходит воркеру в поле `env` команды `start_bot` (stdin, в логи не пишется).
3. Воркер применяет переменные на время загрузки бота и отключает `load_dotenv()` бота, чтобы тот не подхватил чужой `.env` выше по дереву папок (например, `.env` самой панели).
4. Старый `.env` в папке бота удаляется. Если в нём были реальные `ADMIN_IDS`, а в БД пусто, они сначала переносятся в БД.

Без воркера (`USE_WORKER_POOL=false`) переменные передаются в окружение процесса бота.

## Изменение настроек

Переключатели токена (защита контента, сохранение медиа, userbot, уровень логов и т.д.) и список админов меняют только БД — в обоих режимах. Новые значения бот получает при следующем запуске. Раньше роуты дописывали `.env` на лету, причём поиск папки по `PROJECT_ID=<id>` задевал и другие проекты (например, 1 → 10–19); теперь этого нет.

## Что не меняется

- Экспорт проекта по-прежнему содержит `.env` — он формируется на клиенте.
- `GET /api/projects/:id/admin-ids` читает старый `.env`, только если в БД пусто.

## Ограничение

Переменные применяются к `os.environ` воркера только на время загрузки бота. Код, который читает `os.getenv` позже, во время работы (оплата, `psql_query`, HTTP-запрос с env-переменными), в общем воркере с несколькими ботами может увидеть чужие или пустые значения. Это было и с файлом `.env`, режим `inline` этого не меняет.
