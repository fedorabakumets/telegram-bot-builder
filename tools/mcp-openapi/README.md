# Ограниченный OpenAPI-адаптер

Это альтернативный локальный stdio-адаптер для клиентов, которым нужен сгенерированный из OpenAPI интерфейс. Основной интерфейс BotCraft — общий реестр действий полного или компактного MCP. Данный адаптер не является автоматической публикацией всего HTTP API и не должен использоваться для обхода ограничений основного MCP.

`prepare-spec.mjs` читает `docs/api/openapi.json`, сохраняет стабильные operationId и переводит авторизацию в Bearer PAT. Политика `exposure.mjs` публикует пять явно проверенных GET-операций: health, список ботов, список проектов, чтение проекта и статусы ботов проекта. Неизвестный путь или метод закрыт даже с разрешённым тегом. Административные операции, персональные ключи, токены ботов, ENV, секреты и управление коллабораторами запрещены отдельно. Права проекта всё равно проверяются HTTP-сервером. Для изменений и остальных возможностей используйте основной MCP.

Сначала обновите документацию офлайн: `npx tsx scripts/generate-api-docs.ts`, затем подготовьте подмножество: `node tools/mcp-openapi/prepare-spec.mjs`. Генерация клиента через `npm run mcp:openapi:generate` отдельно устанавливает зависимости и требует соответствующего окружения; подготовка JSON сама сеть не использует. После изменения политики ранее сгенерированный клиент нужно пересобрать. `start.ts` до импорта generated проверяет определения маршрутов статическим разбором: устаревший клиент с PAT/ENV либо неизвестным форматом откажется запускаться. Проверка не выполняет код generated. Запуск самого файла generated напрямую обходит wrapper и не является поддерживаемым способом запуска.

В текущем worktree клиент уже пересобран локально установленным CLI. Проверка `npx tsx tools/mcp-openapi/smoke-client.ts` запускает настоящий stdio-wrapper с фиктивным ключом и недоступным HTTP-адресом, проверяет ровно пять инструментов через tools/list и закрывает процесс. Это проверка запуска и каталога, не работы HTTP-операций; запросы к API при ней не выполняются. Generated-каталог игнорируется Git, поэтому на другой машине сборка всё равно потребуется.

`docs/api/offline-coverage.json` показывает проверки локальных ссылок, ID, неописанных ответов, оставшиеся старые runtime-only записи и статические кандидаты маршрутов. Кандидаты AST не заменяют запуск изолированного приложения: вложенные Router mounts и динамические пути могут требовать ручного анализа. Офлайн генератор не запускает registerRoutes, задачи, Redis или БД. Старые runtime-only записи сохраняются с `x-offline-unverified`, а не выдаются за заново проверенные контракты.

Проверки политики: `node --test tools/mcp-openapi/exposure.test.mjs tools/mcp-openapi/security.test.mjs`. Проверка защиты от старого клиента: `npx tsx --test tools/mcp-openapi/validate-generated.test.ts`. Проверки офлайн сборки: `npx tsx --test lib/api-docs/offline-document.test.ts`.
