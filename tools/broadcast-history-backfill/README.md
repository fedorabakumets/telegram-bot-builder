# Восстановление истории рассылки

Инструмент дополняет отсутствующий Telegram ID, кнопки и `buttonsPerRow` в `bot_messages` из сохранённых `broadcast_results` и `broadcasts`. Telegram API не вызывается, токены ботов не читаются. Схема БД не меняется.

Запускать из корня репозитория. `DATABASE_URL` нужно заранее установить для нужной базы: инструмент намеренно не читает `.env` и не выбирает окружение автоматически. Все три ограничения обязательны: проект, конкретная рассылка и ID записи бота (не секретный токен).

```powershell
node tools/broadcast-history-backfill/run.mjs --project 12 --broadcast 40 --token 11
```

По умолчанию это **dry-run** в транзакции только для чтения. Вывод содержит только общие количества и причины пропусков, без текста, пользователей, Telegram ID и параметров соединения. План необходимо проверить перед применением. Для явного применения того же ограниченного плана:

```powershell
node tools/broadcast-history-backfill/run.mjs --project 12 --broadcast 40 --token 11 --apply
```

Применение атомарно, в сериализуемой транзакции. При конфликте или ошибке изменения не сохраняются; повторите dry-run. Допускаются только завершённые или остановленные задания: `done`, `stopped`, `failed`.

Безопасные ограничения:

- Для пользователя должна быть ровно одна запись истории и ровно один результат выбранной рассылки. Дубли не объединяются, пропускаются.
- Нужен успешный результат доставки с Telegram ID и совпадающие текст, тип сообщения и признаки рассылки в истории.
- Существующие конфликтующие ID, кнопки или раскладка не перезаписываются.
- Полностью заполненные записи не меняются; прочие поля `message_data` сохраняются.
- Инструмент восстанавливает сохранённые данные, а не проверяет фактическое состояние сообщения в Telegram. Ошибочно переписанный ранее текст не восстанавливается. При сомнении в прежних ручных правках клавиатуры не применяйте backfill к этой рассылке.

Проверка чистого сопоставления без БД:

```powershell
node --test tools/broadcast-history-backfill/matching.test.mjs
```
